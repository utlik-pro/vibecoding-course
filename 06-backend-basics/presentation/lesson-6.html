Первый бэкенд-код: API Route + Server Action

Напишем два варианта одного и того же — «получить транзакции из базы». Классика (API Route) и современный путь (Server Action в Next.js 16). Поймёте, когда какой использовать.

Что вы сделаете:

  • Создадите API Route GET /api/transactions — классика, работает откуда угодно
  • Перепишете то же через Server Action — современный путь 2026
  • Откроете в браузере, увидите JSON с реальными данными из Supabase
  • Добавите фильтрацию: только доходы или только расходы
Заметка для преподавателя

Это ключевой урок! Студенты впервые создают настоящий API. Результат виден сразу в браузере — это мотивирует! Используйте Cursor для генерации кода.

🔧 Практика 1: Создаём API endpoint

Используйте Cursor для создания API:

Шаг 1: Откройте Cursor

  1. Нажмите Cmd+K (Mac) или Ctrl+K (Windows)
  2. Введите промпт ниже
Промпт для Cursor 
Создай файл app/api/transactions/route.ts для Money Tracker:

1. GET endpoint — получить все транзакции из Supabase
2. Импортируй supabase из lib/supabase
3. Отсортируй по дате (новые первые)
4. Верни JSON с данными
5. Обработай ошибки (статус 500)

Ожидаемый результат от Cursor:

app/api/transactions/route.ts 
import { NextResponse } from 'next/server'
import { supabase } from '@/lib/supabase'

export async function GET() {
  try {
    const { data, error } = await supabase
      .from('transactions')
      .select('*')
      .order('date', { ascending: false })

    if (error) {
      return NextResponse.json(
        { error: error.message },
        { status: 500 }
      )
    }

    return NextResponse.json(data)
  } catch (error) {
    return NextResponse.json(
      { error: 'Internal Server Error' },
      { status: 500 }
    )
  }
}

🔧 Практика 4: Добавляем фильтрацию

Сделаем API умнее — добавим возможность фильтровать транзакции!

Хотим получить только расходы или только доходы:

  • /api/transactions — все транзакции
  • /api/transactions?type=income — только доходы
  • /api/transactions?type=expense — только расходы
Промпт для Cursor 
Добавь в GET функцию фильтрацию по типу транзакции:
- Получи параметр ?type из URL (request.nextUrl.searchParams)
- Если type указан, фильтруй по нему (.eq('type', type))
- Если не указан, верни все транзакции

Обновлённый код:

app/api/transactions/route.ts 
import { NextRequest, NextResponse } from 'next/server'
import { supabase } from '@/lib/supabase'

export async function GET(request: NextRequest) {
  try {
    // Получаем параметр type из URL
    const type = request.nextUrl.searchParams.get('type')

    // Базовый запрос
    let query = supabase
      .from('transactions')
      .select('*')
      .order('date', { ascending: false })

    // Если указан тип — фильтруем
    if (type) {
      query = query.eq('type', type)
    }

    const { data, error } = await query

    if (error) {
      return NextResponse.json({ error: error.message }, { status: 500 })
    }

    return NextResponse.json(data)
  } catch (error) {
    return NextResponse.json({ error: 'Internal Server Error' }, { status: 500 })
  }
}
