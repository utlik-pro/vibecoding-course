Что такое бэкенд? (простыми словами)

Бэкенд — это «невидимая часть» сайта, которая считает, сохраняет и проверяет данные. Разберёмся на примере Money Tracker — простого приложения для учёта личных финансов.

Наша цель: Money Tracker

Практика 1: В чём проблема?

Задание: Откройте DevTools в браузере (F12) и посмотрите на localStorage:

Console (F12 → Console) 
localStorage.setItem('my_balance', '50000');
localStorage.getItem('my_balance');
// Результат: "50000"

Теперь представьте проблемы:

Что случится Результат
Откроете сайт на другом устройстве Данных нет — они только на этом компьютере
Очистите кэш браузера Всё удалится
Кто-то откроет DevTools Увидит все ваши данные
Вывод: Хранить важные данные только в браузере — плохая идея. Нужен бэкенд!
Фронтенд vs Бэкенд (на примере Money Tracker)
🖥️

Фронтенд

Что видит пользователь:
• Кнопка "Добавить расход"
• Форма с полями
• Список транзакций
• Красивые цвета

⚙️

Бэкенд

Что делает сервер:
• Сохраняет транзакцию в базу
• Проверяет что сумма > 0
• Возвращает список транзакций
• Удаляет записи

🗄️

База данных

Где хранятся данные:
• Все транзакции
• Суммы и категории
• Даты операций
• Навсегда в облаке

Аналогия "Ресторан": Фронтенд = зал ресторана (красиво), Бэкенд = кухня (готовит), База данных = склад (хранит). Подробнее в глоссарии →
Практика 2: Смотрим настоящий API

Задание: Откройте в новой вкладке браузера эту ссылку:

URL 
https://jsonplaceholder.typicode.com/posts/1

Вы увидите что-то вроде:

json 
{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat...",
  "body": "quia et suscipit..."
}
Что произошло: Вы только что вызвали API! Бэкенд вернул вам данные в формате JSON. Наш Money Tracker будет работать точно так же — только вместо постов будут транзакции.
Практика 3: Планируем данные Money Tracker

Задание: Подумайте, какие данные нужно хранить для каждой транзакции?

Например, для записи "Потратил 350 рублей на такси вчера" нужно:

Поле Значение Зачем?
amount 350 Сумма транзакции
type "expense" Расход или доход
category "Транспорт" Для группировки
description "Такси до работы" Комментарий
date "2024-01-15" Когда было
JSON — так будет выглядеть одна транзакция 
{
  "id": 1,
  "amount": 350,
  "type": "expense",
  "category": "Транспорт",
  "description": "Такси до работы",
  "date": "2024-01-15"
}
Это структура данных, которую мы создадим в Supabase в уроке 5. Пока просто запомните — всё просто!
Как всё работает вместе

Путь данных когда вы добавляете расход:

Архитектура Money Tracker 
1. Вы нажимаете "Добавить расход 350р на такси"
                    ↓
2. Фронтенд (React) вызывает Server Action в Next.js
                    ↓
3. Server Action получает данные и проверяет их
                    ↓
4. Сохраняет в Supabase (это и есть наша база данных)
                    ↓
5. Supabase отвечает: "Сохранено! ID = 42"
                    ↓
6. Страница автоматически обновляется
                    ↓
7. Вы видите новую транзакцию в списке
Server Action — это новый способ в Next.js 16 писать бэкенд-логику. Раньше нужны были «API Routes» (отдельные файлы для запросов). Сейчас можно прямо в компоненте написать «эта функция работает на сервере» — и Next.js сам разберётся. Подробно — в уроке 6.2 и 6.6.
