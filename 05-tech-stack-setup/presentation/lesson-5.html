Выкладываем сайт в интернет — Vercel

Что вы сделаете:

  • Поймёте, что такое деплой и зачем он нужен
  • Загрузите свой код в GitHub (бесплатно, на всю жизнь)
  • Подключите GitHub к Vercel — каждый git push станет автодеплоем
  • Получите ссылку вида mood-tracker.vercel.app, которой можно поделиться
Заметка для преподавателя

Vercel UI на май 2026: в новом дашборде Environments объединены в один экран, Domains настраиваются по-новому. Если у студента старый аккаунт — может видеть legacy-вид; помогите переключиться на новый.

Время: ~3 мин про деплой, ~7 мин Git+GitHub, ~10 мин подключение Vercel, ~3 мин env vars, ~2 мин чек-лист.

Совет: Покажите экран — этот урок очень визуальный. После клика «Deploy» через минуту сайт уже работает. Для новичков это вау-момент.

1. Что такое деплой (простыми словами)

Сейчас ваш сайт работает только у вас на ноутбуке (localhost:3000). Если ноутбук закрыт — сайта нет. Если друг введёт этот адрес у себя — он увидит свой собственный localhost, а не ваш сайт.

Деплой — это «переезд» вашего сайта с ноутбука на сервер в интернете. После деплоя сайт работает 24/7 по постоянной ссылке, которую можно дать кому угодно.

Vercel — это компания, которая сделала Next.js. Они же предоставляют сервер для деплоя — бесплатно для учебных проектов. Удобство: Vercel «знает» Next.js наизусть и настраивает всё за вас.

Бесплатный план Vercel (Hobby) хватает для пет-проектов и обучения: один разработчик, безлимитные сайты, 100 ГБ трафика в месяц. Для коммерции потом — Pro ($20/мес).
2. Загружаем код на GitHub

Vercel не умеет «брать» код прямо с вашего ноутбука. Сначала нужно положить код в GitHub — это «облачный шкаф» для кода, который видит весь интернет (или только вы — выбираете). Vercel будет читать код оттуда.

Шаг 1 — создать аккаунт GitHub

Зайдите на github.com, зарегистрируйтесь. Бесплатно навсегда.

Шаг 2 — установить gh CLI

gh — это утилита GitHub для терминала. С ней не нужно ходить в браузер каждый раз.

bash 
# Mac
brew install gh

# Windows
winget install --id GitHub.cli

# Логинимся (один раз)
gh auth login

Шаг 3 — отправить проект на GitHub

В корне проекта выполните:

bash 
# Создаём «локальную» git-историю
git init
git add .
git commit -m "Первый коммит — проект MoodTracker"

# Создаём приватный репозиторий и пушим туда код
gh repo create mood-tracker --private --source=. --push

После этого ваш код лежит на github.com/ваш-логин/mood-tracker. Никто кроме вас его не увидит (флаг --private).

🤓 Что такое git, commit, push — в трёх словах
  • Git — это «машина времени» для ваших файлов. Сохраняет каждую версию проекта.
  • Коммит — это «снапшот» текущего состояния с подписью «что я сделал». Например: «Добавил страницу логина».
  • Push — это «загрузить мои коммиты на GitHub», чтобы они там тоже сохранились.
  • Pull — наоборот, «скачать с GitHub то, что там есть» (если вы или другой человек что-то закоммитили туда).
3. Подключаем Vercel

Теперь — самое приятное. Деплой займёт меньше двух минут.

Шаг 1 — зарегистрироваться

Откройте vercel.com и нажмите «Sign Up». Войти лучше через GitHub — Vercel сразу увидит ваши репозитории.

Шаг 2 — импортировать проект

  1. На дашборде нажмите Add New → Project
  2. В списке репозиториев найдите mood-tracker, нажмите Import
  3. Vercel сам определит, что это Next.js. Никаких настроек менять не нужно
  4. Нажмите Deploy

Через 30–60 секунд увидите салют (буквально, такая анимация) и ссылку на ваш сайт: mood-tracker-xxx.vercel.app.

Готово! Скиньте ссылку другу — он увидит ваш сайт. Это уже больше, чем многие делают за месяцы курсов.
4. Магия автодеплоя

Самое крутое: теперь каждый раз, когда вы делаете git push, Vercel автоматически пересобирает и публикует сайт. Без единого клика мышью.

Попробуйте:

  1. Поменяйте текст на главной странице (src/app/page.tsx)
  2. В терминале: git add . && git commit -m "Поменял заголовок" && git push
  3. Откройте Vercel дашборд — увидите «Building...», потом «Ready»
  4. Обновите ссылку vercel.app — изменения уже там

Preview-деплои для веток

Если запушите код в другую ветку (не main), Vercel сделает отдельный preview-сайт по уникальной ссылке. Можно показывать заказчику или тестировать новую фичу, не трогая «боевой» сайт.

Ветка Что получаете Зачем
main mood-tracker.vercel.app Боевой сайт для пользователей
feature/login mood-tracker-feature-login-...vercel.app Тестирование новой фичи
5. Переменные окружения (секреты)

Когда подключим Supabase и OpenAI (урок 5.7), у нас появятся ключи API. Их нельзя класть в код — иначе любой сможет их украсть. Кладём в «Environment Variables» Vercel.

Как добавить

  1. В дашборде проекта: Settings → Environment Variables
  2. В новом UI 2026 окружения объединены: можно проставить, в каких из них действует переменная (Production, Preview, Development) галочками
  3. Введите имя (например, OPENAI_API_KEY) и значение, нажмите Save

Локально — файл .env.local

На своём ноутбуке те же переменные положите в файл .env.local в корне проекта:

bash 
# .env.local — НЕ коммитим в Git!
OPENAI_API_KEY=sk-...
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...

Файл .env.local уже добавлен в .gitignore (Next.js делает это сам), поэтому в Git не попадёт. Ваши секреты в безопасности.

Удобный приём — забрать env с Vercel к себе

bash 
# Один раз
npm install -g vercel
vercel link

# Скачать env переменные с Vercel
vercel env pull .env.local

Так на новом ноутбуке или у нового члена команды быстро восстанавливаются все ключи.

Префикс NEXT_PUBLIC_ делает переменную видимой в браузере. Никогда не давайте такой префикс ключам типа OPENAI_API_KEY или SUPABASE_SERVICE_ROLE_KEY — иначе они утекут пользователям.
