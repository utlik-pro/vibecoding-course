Урок 5.6 ⏱ 35 минут

Как просить ИИ — чтобы получалось то, что нужно

Что вы сделаете:

  • Поймёте формулу хорошего промпта (контекст + задача + требования + формат)
  • Получите шаблоны на 5 типичных задач: компонент, API, баг, рефакторинг, документация
  • Научитесь использовать «Plan mode» в Claude Code для крупных задач
  • Соберёте свой prompts.md — личную библиотеку шаблонов
Заметка для преподавателя

Ключевой урок модуля: качество промптов = качество кода. Покажите на одной задаче «плохой промпт» vs «хороший промпт» — разница в результате говорит сама за себя.

Время: ~10 мин формула, ~15 мин шаблоны, ~5 мин Plan mode, ~5 мин prompts.md.

Май 2026: модели стали умнее (Claude Sonnet 4.6, GPT-5) и сами додумывают пробелы — но всё равно лучше дать им контекст в нужной форме, чем «угадывайте за меня».

1. Формула хорошего промпта

Хороший промпт всегда отвечает на четыре вопроса:

Вопрос Что включить Пример
Контекст Что за проект, какой стек «В Next.js 16 проекте с shadcn/ui...»
Задача Что нужно сделать «...сделай компонент карточки пользователя»
Требования Конкретные ограничения и поля «...с аватаром, именем, email и кнопкой Edit»
Формат Как должен выглядеть результат «...файл по адресу src/components/UserCard.tsx, типизированные пропсы»

Сравните

Плохой промпт: «Сделай форму»
ИИ выдумает поля, выберет произвольный стек, положит файл «куда-то».
Хороший промпт: «В Next.js 16 проекте сделай форму регистрации (email, пароль, подтверждение пароля). Используй shadcn/ui Form, Input, Button. Валидация через zod. Файл — src/app/(auth)/register/page.tsx.»
ИИ напишет ровно то, что нужно — с первого раза.
Помните про AGENTS.md: если он у вас уже есть (урок 5.3), большую часть «Контекста» можно опустить — ИИ знает стек и структуру. Концентрируйтесь на «Задаче» и «Требованиях».
2. Готовые шаблоны на типичные задачи
🧩 Шаблон 1 — Создать компонент
prompt 
Создай компонент [имя] для [назначение].

Что должен показывать:
- [пункт 1]
- [пункт 2]

Props:
- [имя]: [тип] - [что это]

Использовать готовые компоненты из shadcn/ui (Card, Button и т.д.).
Файл: src/components/[ИмяКомпонента].tsx
🔌 Шаблон 2 — Создать API-роут
prompt 
Создай API-роут для [действие].

Endpoint: /api/[путь]
Метод: [GET / POST / PUT / DELETE]

Что приходит на вход:
- [поле]: [тип]

Что возвращаем:
- При успехе: { data: [...] }
- При ошибке: { error: "сообщение" } со статусом 400 или 500

Использовать [Supabase / OpenAI].
Валидировать вход через zod, оборачивать в try/catch.
🐛 Шаблон 3 — Исправить баг
prompt 
В файле [путь] происходит баг.

Что я делаю: [шаги воспроизведения]
Что вижу: [что происходит на экране/в консоли]
Что должно быть: [ожидаемое поведение]

Сообщение об ошибке (если есть):
[текст ошибки или stack trace]

Сначала найди корневую причину, потом точечно исправь.
Не рефактори вокруг — только баг.
♻️ Шаблон 4 — Отрефакторить кусок
prompt 
Отрефактори [файл / функция / компонент].

Цель: [что хочется улучшить — читаемость / разбить на части / убрать дубли]

Что НЕ делать:
- Не менять поведение (видимые пользователю функции остаются те же)
- Не вводить новых зависимостей без согласования
- Не переименовывать публичные API (экспортируемые функции)

Покажи план изменений до того, как править файлы.
📚 Шаблон 5 — Объяснить кусок кода
prompt 
Объясни, что делает код в [файл / выделенный кусок].

Я новичок, разберись с предположением что я не знаю
эту тему. Используй простые слова и аналогии.

Если встретится сложный термин — поясни в скобках.

В конце — одно предложение «зачем этот код вообще нужен».
3. Plan mode для больших задач

Когда задача большая (страница с формой, авторизацией и валидацией) — попросите ИИ сначала составить план, а потом писать код. В Claude Code для этого есть отдельный режим.

В Claude Code

Внутри сессии нажмите Shift+Tab — появится «Plan mode». Теперь ИИ только продумает решение, не трогая файлы. Когда план одобрите — нажмите Shift+Tab ещё раз и Claude его выполнит.

В Cursor

Просто добавьте в начало промпта: «Сначала покажи план изменений (какие файлы создаёшь/правишь и что в них). Я скажу „поехали“ — тогда напишешь код.»

Зачем это нужно

  • Дешевле исправить план, чем код. Если ИИ собрался лезть не туда — поправить пару строчек плана быстрее, чем отменять кучу файлов
  • Видно, чего ИИ не знает. Если в плане «доделать функцию X» — а её у вас нет, обнаружится сразу
  • Учитесь сами. Прочитав план, понимаете, как ИИ думает — это лучшая школа
Когда план не нужен: для маленьких задач (изменить текст, добавить кнопку) — пишите сразу. Plan mode тратит время и токены, не нужно использовать его на каждый чих.
4. 7 правил, которые экономят часы
  1. Один промпт = одна задача. Если хочется попросить «сделай форму И добавь её в навигацию И задеплой» — разбейте на три промпта.
  2. Прикрепите файл, а не описывайте. В Cursor: @ + имя файла. В Claude Code: «прочитай файл X». Так ИИ видит реальный код, а не вашу версию его.
  3. Скажите «не делай», а не только «сделай». Запреты («не используй any», «не меняй другие файлы») работают сильнее.
  4. После генерации — прочитайте код. ИИ ошибается. На 100% довериться можно только после ревью своими глазами.
  5. Сохраните успешные промпты. Получился классный промпт — добавьте в prompts.md. Через месяц спасёте полчаса.
  6. Не бойтесь итерировать. Первый ответ редко идеален. «Перепиши, теперь без X», «добавь Y» — это нормальная работа.
  7. Используйте новые сессии. Когда переключаетесь на новую задачу — /clear в Claude Code или новый чат. Старый контекст путает ИИ.
5. Соберите свой prompts.md

Создайте в корне проекта файл prompts.md с шаблонами под ваши задачи. Структура:

markdown 
# Промпты для MoodTracker

## Создать компонент
[вставьте Шаблон 1 из этого урока]

## Создать API-роут
[вставьте Шаблон 2]

## Исправить баг
[вставьте Шаблон 3]

## Свой промпт — генерация AI-инсайта
В рамках MoodTracker создай функцию generateInsight(moods).
Принимает массив записей за неделю, возвращает строку
с советом до 200 слов через gpt-4o-mini.
Системный промпт: "Ты эмпатичный коуч по эмоциональному здоровью..."

## Свой промпт — добавить shadcn компонент
Добавь в проект компонент [имя] из shadcn/ui:
выполни npx shadcn@latest add [имя], проверь что он
появился в src/components/ui/ и сразу импортни в
src/app/page.tsx как пример.
Совет: через 1–2 месяца ваш prompts.md станет вашим главным активом. Промпты, которые сработали один раз, сработают и второй. Не теряйте их.
