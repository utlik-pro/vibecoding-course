Task Master — планирование проекта с ИИ

Цели урока:

  • Понять, зачем нужен Task Master и как он встраивается в вайбкодинг
  • Установить task-master-ai и настроить модели
  • Написать PRD для проекта MoodTracker (трекер настроения)
  • Сгенерировать список задач и подзадач из PRD
  • Освоить ежедневный цикл: next → show → set-status done
Заметка для преподавателя

Идея урока: студенты только что описали проект в CLAUDE.md — теперь Task Master превратит описание в конкретные задачи. Покажите весь цикл на сквозном примере MoodTracker, чтобы каждая команда имела результат на экране.

Время: ~5 мин теория, ~10 мин установка и модели, ~10 мин PRD, ~10 мин parse-prd + expand, ~10 мин daily loop.

Совет: запустите task-master list в конце — студенты увидят красивую таблицу задач и поймут, ради чего весь этот процесс.

1. Зачем нужен Task Master

Когда у вас есть идея проекта — Cursor и Claude Code умеют писать код. Но они не помнят, что вы уже сделали, что осталось, и в каком порядке делать. Без плана вайбкодинг превращается в хаос: ИИ перескакивает между фичами, забывает зависимости, переписывает уже готовое.

Task Master — это CLI и MCP-инструмент, который:

  • Превращает PRD (описание проекта) в список задач
  • Разбивает большие задачи на подзадачи с зависимостями
  • Хранит статус каждой задачи (pending, in-progress, done)
  • Подсказывает, какую задачу делать следующей
  • Логирует прогресс прямо в задачу — Claude Code и Cursor получают контекст
Как это связано с CLAUDE.md: в прошлом уроке мы научили Claude Code, каким мы хотим видеть код. Task Master отвечает на другой вопрос — что делать дальше и в каком порядке.

Сквозной пример урока — MoodTracker

Все команды мы будем выполнять на одном проекте: MoodTracker — мини-веб-приложение, где пользователь раз в день отмечает настроение (1–5), пишет заметку и видит график за месяц. Раз в неделю ИИ даёт инсайт по записям.

📅

Ежедневная запись

Настроение 1–5 и короткая заметка

📈

Дашборд

График за 30 дней + средние

🤖

AI-инсайты

Раз в неделю советы от gpt-4o-mini

🔐

Auth

Магик-линк через Supabase

2. Установка и инициализация

В корне Next.js проекта (созданного в уроке 5.1) выполните:

bash 
# Установка глобально (рекомендуется)
npm install -g task-master-ai

# Проверка установки
task-master --version

# Инициализация в проекте
cd my-saas-app
task-master init

После init в проекте появится папка .taskmaster/:

Структура 
.taskmaster/
├── config.json              # Настройки моделей
├── docs/
│   └── prd.txt              # Сюда напишем PRD
├── tasks/
│   └── tasks.json           # Сгенерированные задачи (пока пусто)
└── templates/
    └── example_prd.txt      # Шаблон PRD для справки
Важно: tasks.json и config.json редактируются командами Task Master — не правьте их вручную. Файлы задач в tasks/ регенерируются автоматически.
3. Настройка моделей

Task Master использует ИИ для парсинга PRD и генерации задач. Нужно указать, какие модели использовать. Запустите интерактивный мастер:

bash 
task-master models --setup

Мастер спросит про три роли:

Роль Для чего Что выбрать
main Основная модель — генерирует задачи и подзадачи Claude Sonnet (если есть ANTHROPIC_API_KEY) или GPT-4o
research Опционально — модель для глубокого ресёрча с веб-поиском Можно пропустить или поставить ту же main-модель
fallback Запасная модель, если основная упала gpt-4o-mini — дешевле и стабильно
Без Perplexity: для research-роли в документации советуют Perplexity, но ключ платный. Для учебного проекта смело пропускайте research или поставьте ту же модель, что и main — флаг --research просто не будет подключаться, но всё остальное работает.

Где взять ключи

Создайте файл .env в корне проекта (рядом с .env.local) и добавьте ключи только тех провайдеров, которыми пользуетесь:

bash 
# .env (для Task Master CLI)
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
# PERPLEXITY_API_KEY=... — необязательно

Проверьте текущую конфигурацию:

bash 
task-master models

Команда покажет таблицу с моделями для каждой роли и статусом доступа к API.

4. Пишем PRD для MoodTracker

PRD (Product Requirements Document) — это короткое описание того, что мы строим. Task Master читает его и превращает в задачи.

Откройте .taskmaster/docs/prd.txt и замените содержимое на наш PRD:

markdown 
# MoodTracker — Product Requirements Document

## Обзор
MoodTracker — веб-приложение для ежедневного трекинга настроения
с AI-инсайтами. Пользователь записывает настроение по шкале 1–5
и короткую заметку, видит график за месяц, раз в неделю получает
рекомендацию от ИИ на основе своих записей.

## Технический стек
- Next.js 14 (App Router) + TypeScript
- Supabase (Auth + Postgres + Row Level Security)
- Tailwind CSS + shadcn/ui
- OpenAI API (модель gpt-4o-mini)
- Recharts для графиков
- Vercel для хостинга

## Основные функции

### 1. Аутентификация
- Регистрация и вход по магик-линку (Supabase Auth)
- Защищённые роуты для авторизованных пользователей
- Кнопка "Выйти" в шапке

### 2. Запись настроения
- Форма "Как ты сегодня?" с выбором значения 1–5
- Опциональная заметка до 280 символов
- Одна запись в день, можно отредактировать в течение дня
- Сохранение в Postgres с user_id и timestamp

### 3. Дашборд
- График настроения за 30 дней (line chart)
- Среднее настроение за неделю и месяц
- Streak — сколько дней подряд была запись

### 4. AI-инсайты
- Кнопка "Получить инсайт" доступна раз в неделю
- ИИ читает записи за неделю и пишет короткий совет (до 200 слов)
- Используется gpt-4o-mini, ответ кэшируется в БД

### 5. Настройки
- Часовой пояс пользователя
- Удаление аккаунта со всеми записями

## Структура БД
- profiles (id, email, timezone) — связана с auth.users
- moods (id, user_id, value 1-5, note, created_at)
- insights (id, user_id, content, week_start, created_at)

## Этапы разработки
1. Настройка проекта: Next.js, Tailwind, shadcn/ui
2. Подключение Supabase и схема БД с RLS
3. Аутентификация по магик-линку
4. Форма ежедневной записи настроения
5. Дашборд с графиком за 30 дней
6. AI-инсайты через OpenAI
7. Настройки и удаление аккаунта
8. Деплой на Vercel
Совет: чем точнее этапы и функции — тем лучше задачи. Не нужно писать диссертацию: 1–2 страницы достаточно. Если сомневаетесь — попросите Claude Code сгенерировать PRD: "Сделай PRD для MoodTracker по шаблону .taskmaster/templates/example_prd.txt".
5. Генерируем задачи из PRD

Запустите парсинг — Task Master прочитает PRD и создаст задачи:

bash 
task-master parse-prd .taskmaster/docs/prd.txt
Терпение: команда делает запрос к ИИ — занимает 30–90 секунд. Не прерывайте.

Результат — список задач. Посмотреть его:

bash 
task-master list

Для MoodTracker получится примерно 8–10 задач:

пример вывода 
┌────┬─────────────────────────────────────┬──────────┬──────────┐
│ ID │ Title                               │ Status   │ Priority │
├────┼─────────────────────────────────────┼──────────┼──────────┤
│ 1  │ Setup Next.js project with stack    │ pending  │ high     │
│ 2  │ Configure Supabase client and env   │ pending  │ high     │
│ 3  │ Create database schema with RLS     │ pending  │ high     │
│ 4  │ Implement magic-link authentication │ pending  │ high     │
│ 5  │ Build daily mood entry form         │ pending  │ medium   │
│ 6  │ Build dashboard with mood chart     │ pending  │ medium   │
│ 7  │ Add weekly AI insight generation    │ pending  │ medium   │
│ 8  │ Settings page and account deletion  │ pending  │ low      │
│ 9  │ Deploy to Vercel                    │ pending  │ medium   │
└────┴─────────────────────────────────────┴──────────┴──────────┘

Каждая задача автоматически получает id, priority, dependencies и testStrategy. Посмотреть детали одной задачи:

bash 
task-master show 4
6. Разбиваем большие задачи на подзадачи

Задача "Implement magic-link authentication" слишком большая для одного захода. Сначала спросим у Task Master, какие задачи реально сложные:

bash 
task-master analyze-complexity

Команда оценит каждую задачу по сложности от 1 до 10 и порекомендует, сколько подзадач нужно. Открыть отчёт:

bash 
task-master complexity-report

Теперь разбиваем все подходящие задачи на подзадачи одной командой:

bash 
task-master expand --all

Или раскрываем только конкретную задачу:

bash 
task-master expand --id=4

После этого task-master show 4 покажет подзадачи 4.1, 4.2, 4.3 и т.д.:

пример 
Task 4: Implement magic-link authentication
├── 4.1 Install @supabase/ssr and configure middleware
├── 4.2 Create login page with email input
├── 4.3 Build /auth/callback route handler
├── 4.4 Protect dashboard routes server-side
└── 4.5 Add sign-out button to header
Зачем подзадачи: одна подзадача = один промпт в Cursor/Claude Code. Большие задачи плохо помещаются в контекст ИИ — он начинает "забывать" детали. Подзадачи решают эту проблему.
7. Ежедневный цикл разработки

Когда задачи готовы — каждое утро вы запускаете один и тот же цикл:

Шаг 1 — узнать, что делать
bash 
task-master next

Task Master посмотрит на статусы и зависимости и предложит следующую задачу. Например, 4.1 Install @supabase/ssr and configure middleware.

Шаг 2 — изучить детали
bash 
task-master show 4.1

Получаете описание, требования и стратегию тестирования. Этот текст можно скопировать в Cursor Composer как промпт.

Шаг 3 — отметить "в работе"
bash 
task-master set-status --id=4.1 --status=in-progress
Шаг 4 — реализовать через ИИ

Открываете Cursor Composer (Cmd/Ctrl+I) или запускаете claude в терминале. Передаёте описание подзадачи как контекст:

prompt 
Реализуй задачу 4.1 из Task Master:
[вставляем содержимое task-master show 4.1]

Стек проекта описан в CLAUDE.md.
Подзадача должна быть атомарной — не трогай другие части.
Шаг 5 — записать прогресс

Если что-то узнали в процессе — залогируйте это в подзадачу. Эта заметка станет контекстом для следующих задач:

bash 
task-master update-subtask --id=4.1 --prompt="Поставил @supabase/ssr вместо @supabase/auth-helpers (deprecated). Middleware кладёт сессию в cookies."
Шаг 6 — закрыть задачу
bash 
task-master set-status --id=4.1 --status=done
task-master next   # повторяем цикл
Главная мысль: в любой момент task-master list покажет вам полную картину проекта. Это ваш "северный полюс" — особенно когда вернулись после паузы и забыли, на чём остановились.
8. Связка с Claude Code и Cursor

Task Master умеет работать как MCP-сервер — это значит, что Claude Code и Cursor могут вызывать его команды напрямую, не выходя в терминал.

Подключение MCP в Claude Code

Создайте файл .mcp.json в корне проекта:

json 
{
  "mcpServers": {
    "task-master-ai": {
      "command": "npx",
      "args": ["-y", "--package=task-master-ai", "task-master-ai"],
      "env": {
        "ANTHROPIC_API_KEY": "sk-ant-...",
        "OPENAI_API_KEY": "sk-..."
      }
    }
  }
}

Теперь внутри сессии claude можно говорить человеческим языком:

claude 
> Покажи следующую задачу из Task Master
> Какие подзадачи у задачи 4?
> Отметь подзадачу 4.1 как done и покажи следующую

Claude Code сам вызовет next_task, get_task, set_task_status через MCP.

Если MCP не подключился — это не страшно. CLI-команды task-master * работают всегда. MCP — просто удобство для голосовых запросов.

Команда Что делает
