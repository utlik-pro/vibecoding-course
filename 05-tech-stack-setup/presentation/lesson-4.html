Task Master — превращаем идею в список задач

Что вы сделаете:

  • Поймёте, зачем нужен «менеджер задач для ИИ» поверх Cursor и Claude Code
  • Установите Task Master и подключите модели (без обязательного Perplexity)
  • Напишете «бриф» проекта (PRD) для MoodTracker
  • Превратите бриф в готовый список задач и подзадач
  • Освоите ежедневный цикл: спросить «что дальше», сделать, отметить готово
Заметка для преподавателя

Идея урока: студенты только что описали проект в AGENTS.md — Task Master разворачивает описание в конкретные задачи. Покажите весь цикл на сквозном MoodTracker, чтобы каждая команда давала видимый результат.

Время: ~5 мин зачем, ~10 мин установка/модели, ~10 мин PRD, ~10 мин parse-prd + expand, ~10 мин daily loop.

Финал: запустите task-master list — таблица из 8–10 задач даёт «вау-эффект» и обоснование всего урока.

1. Зачем нужен Task Master

У Cursor и Claude Code есть слепое пятно: они не помнят, что вы уже сделали и что осталось. Каждый раз начинаете заново. Без плана разработка превращается в хаос — ИИ перескакивает между фичами, забывает зависимости, переписывает уже готовое.

Task Master закрывает эту дыру. Он:

  • Берёт ваше описание проекта и превращает в список задач
  • Разбивает большие задачи на маленькие подзадачи
  • Помнит, какие задачи закрыты, а какие в работе
  • Подсказывает, что делать следующим с учётом зависимостей
  • Сохраняет ваши заметки прямо в задачу — в следующей сессии Claude Code или Cursor увидит контекст
Связка с предыдущим уроком: в AGENTS.md вы описали, каким вы хотите видеть код. Task Master отвечает на другой вопрос — что делать прямо сейчас.

Сквозной пример: MoodTracker

Тот же проект, что и в уроках 5.1–5.3. Раз в день записываем настроение от 1 до 5 и заметку, видим график за месяц, раз в неделю получаем совет от ИИ.

2. Установка

В корне Next.js проекта (созданного в уроке 5.1) выполните в терминале:

bash 
# Установка глобально
npm install -g task-master-ai

# Проверка
task-master --version

# Инициализация в проекте
cd mood-tracker
task-master init

После init в проекте появится папка .taskmaster/:

Структура 
.taskmaster/
├── config.json              ← настройки моделей
├── docs/
│   └── prd.txt              ← сюда положим описание проекта
├── tasks/
│   └── tasks.json           ← сгенерированные задачи (пока пусто)
└── templates/
    └── example_prd.txt      ← шаблон PRD для справки
Важно: файлы tasks.json и config.json — служебные, редактируйте их только командами Task Master, не руками.
3. Подключаем модели (без Perplexity)

Task Master использует ИИ для парсинга PRD и генерации задач. Запустите интерактивный мастер:

bash 
task-master models --setup

Мастер спросит про три роли:

Роль Для чего Что выбрать (май 2026)
main Основная — генерирует задачи и подзадачи Claude Sonnet 4.6 (нужен ANTHROPIC_API_KEY) или GPT-5
research Опционально — для глубокого ресёрча с веб-поиском Можно пропустить или выбрать ту же main-модель
fallback Запасная, если основная упала gpt-4o-mini — дешево и стабильно
Без Perplexity: в документации советуют Perplexity для research-роли — ключ платный. Для учебного проекта смело пропускайте этот пункт. Флаг --research просто не будет работать, всё остальное — да.

Где взять ключи API

Создайте файл .env в корне проекта (рядом с .env.local) и добавьте только тех провайдеров, которыми пользуетесь:

bash 
# .env (для Task Master)
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
# PERPLEXITY_API_KEY=... — необязательно

Проверить, что всё подключилось:

bash 
task-master models

Команда покажет таблицу с выбранными моделями и статусом доступа к API.

4. Пишем PRD — описание проекта

PRD расшифровывается как Product Requirements Document — «документ с требованиями к продукту». Звучит грозно, но на деле это просто текстовый файл, где вы коротко описываете, что строите. Task Master читает этот файл и превращает в задачи.

Откройте .taskmaster/docs/prd.txt и замените содержимое на это:

markdown 
# MoodTracker — описание проекта

## О чём проект
MoodTracker — сайт для ежедневного трекинга настроения с AI-советами.
Пользователь раз в день отмечает настроение от 1 до 5 и пишет
короткую заметку, видит график за месяц, раз в неделю получает
рекомендацию от ИИ на основе своих записей.

## Технический стек
- Next.js 16 (App Router) + TypeScript
- Supabase (Auth + Postgres + Row Level Security)
- Tailwind CSS 4 + shadcn/ui
- OpenAI API (gpt-4o-mini)
- Recharts для графиков
- Vercel для хостинга

## Главные функции

### 1. Аутентификация
- Вход по магик-линку (Supabase Auth)
- Защищённые страницы для авторизованных
- Кнопка "Выйти" в шапке

### 2. Запись настроения
- Форма "Как ты сегодня?" — кнопки 1-5
- Опциональная заметка до 280 символов
- Одна запись в день, можно редактировать в течение дня
- Сохранение в Postgres с user_id и timestamp

### 3. Дашборд
- График за 30 дней (line chart, Recharts)
- Среднее настроение за неделю и месяц
- Streak — сколько дней подряд была запись

### 4. AI-инсайт
- Кнопка "Получить совет" доступна раз в неделю
- ИИ читает записи за неделю и пишет короткий совет (до 200 слов)
- gpt-4o-mini, ответ кэшируется в БД

### 5. Настройки
- Часовой пояс пользователя
- Удаление аккаунта со всеми записями

## Структура БД
- profiles (id, email, timezone) — связана с auth.users
- moods (id, user_id, value 1-5, note, created_at)
- insights (id, user_id, content, week_start, created_at)

## План разработки
1. Каркас проекта (Next.js, Tailwind, shadcn/ui)
2. Подключение Supabase и схема БД с RLS
3. Аутентификация по магик-линку
4. Форма ежедневной записи
5. Дашборд с графиком
6. AI-инсайты через OpenAI
7. Настройки и удаление аккаунта
8. Деплой на Vercel
Совет: чем точнее этапы и функции — тем лучше задачи. Не нужно писать диссертацию, 1–2 страниц достаточно. Сомневаетесь — попросите Claude Code: «Напиши PRD для MoodTracker по шаблону .taskmaster/templates/example_prd.txt».
5. Превращаем PRD в задачи

Запустите парсинг — Task Master прочитает PRD и создаст задачи:

bash 
task-master parse-prd .taskmaster/docs/prd.txt
Терпение: команда делает запрос к ИИ — занимает 30–90 секунд. Не прерывайте.

Посмотреть результат:

bash 
task-master list

Получится примерно 8–10 задач:

пример вывода 
┌────┬─────────────────────────────────────┬──────────┬──────────┐
│ ID │ Title                               │ Status   │ Priority │
├────┼─────────────────────────────────────┼──────────┼──────────┤
│ 1  │ Setup Next.js project with stack    │ pending  │ high     │
│ 2  │ Configure Supabase client and env   │ pending  │ high     │
│ 3  │ Create database schema with RLS     │ pending  │ high     │
│ 4  │ Implement magic-link authentication │ pending  │ high     │
│ 5  │ Build daily mood entry form         │ pending  │ medium   │
│ 6  │ Build dashboard with mood chart     │ pending  │ medium   │
│ 7  │ Add weekly AI insight generation    │ pending  │ medium   │
│ 8  │ Settings page and account deletion  │ pending  │ low      │
│ 9  │ Deploy to Vercel                    │ pending  │ medium   │
└────┴─────────────────────────────────────┴──────────┴──────────┘

Каждая задача автоматически получает id, priority, dependencies (зависимости — что нужно сделать раньше) и testStrategy (как проверить, что готово). Посмотреть детали одной:

bash 
task-master show 4
6. Большие задачи режем на маленькие

Задача «Implement magic-link authentication» — это 3–5 часов работы. Слишком много для одного промпта. Сначала спросим Task Master, какие задачи реально сложные:

bash 
task-master analyze-complexity

Команда оценит каждую задачу по сложности от 1 до 10 и подскажет, сколько подзадач нужно. Открыть отчёт:

bash 
task-master complexity-report

Теперь разбиваем все подходящие задачи одной командой:

bash 
task-master expand --all

Или раскрываем только конкретную:

bash 
task-master expand --id=4

После этого task-master show 4 покажет подзадачи 4.1, 4.2, 4.3 и т.д.:

пример 
Task 4: Implement magic-link authentication
├── 4.1 Install @supabase/ssr and configure middleware
├── 4.2 Create login page with email input
├── 4.3 Build /auth/callback route handler
├── 4.4 Protect dashboard routes server-side
└── 4.5 Add sign-out button to header
Зачем подзадачи: одна подзадача = один промпт в Cursor/Claude Code. Большие задачи плохо помещаются в «голову» ИИ — он начинает забывать детали. Подзадачи это лечат.
7. Ежедневный цикл

Когда задачи готовы — каждое утро вы запускаете один и тот же ритуал:

Шаг 1 — узнать, что делать
bash 
task-master next

Task Master посмотрит на статусы и зависимости и предложит следующую задачу. Например, 4.1 Install @supabase/ssr and configure middleware.

Шаг 2 — изучить детали
bash 
task-master show 4.1

Получаете описание, требования и стратегию тестирования. Этот текст можно скопировать в Cursor Composer или Claude Code как промпт.

Шаг 3 — отметить «в работе»
bash 
task-master set-status --id=4.1 --status=in-progress
Шаг 4 — реализовать через ИИ

Открываете Cursor Composer (⌘+I) или запускаете claude. Передаёте описание подзадачи как промпт:

prompt 
Реализуй задачу 4.1 из Task Master:
[вставляем содержимое task-master show 4.1]

Стек проекта описан в AGENTS.md.
Подзадача атомарная — не трогай другие части проекта.
Шаг 5 — сохранить заметки

Если что-то узнали в процессе — залогируйте в подзадачу. Эта заметка станет контекстом для следующих:

bash 
task-master update-subtask --id=4.1 --prompt="Поставил @supabase/ssr. Middleware кладёт сессию в cookies."
Шаг 6 — закрыть и взять следующую
bash 
task-master set-status --id=4.1 --status=done
task-master next   # повторяем цикл
Главная мысль: в любой момент task-master list покажет полную картину. Это «северный полюс» — особенно когда вернулись после паузы и забыли, на чём остановились.
8. Подключение к Claude Code через MCP

Task Master умеет работать как MCP-сервер. MCP (Model Context Protocol) — это стандарт 2025 года, позволяющий ИИ-инструментам разговаривать друг с другом. Если коротко: Claude Code и Cursor могут вызывать команды Task Master напрямую, без терминала.

Подключение в Claude Code

Создайте файл .mcp.json в корне проекта:

json 
{
  "mcpServers": {
    "task-master-ai": {
      "command": "npx",
      "args": ["-y", "--package=task-master-ai", "task-master-ai"],
      "env": {
        "ANTHROPIC_API_KEY": "sk-ant-...",
        "OPENAI_API_KEY": "sk-..."
      }
    }
  }
}

Перезапустите claude. Теперь внутри сессии можно говорить человеческим языком:

claude 
> Покажи следующую задачу из Task Master
> Какие подзадачи у задачи 4?
> Отметь подзадачу 4.1 как done и покажи следующую

Claude Code сам вызовет нужные команды Task Master через MCP.

Если MCP не подключился — это не страшно. Все команды task-master * работают и из терминала. MCP — это просто удобство для голосовых запросов.
