Подключаем Supabase и OpenAI

Что вы сделаете:

  • Создадите бесплатный проект в Supabase (база данных + авторизация)
  • Подключите его к Next.js через современный пакет @supabase/ssr
  • Получите ключ OpenAI и подключите модель gpt-4o-mini
  • Сделаете «health check» — endpoint, проверяющий, что всё работает
Заметка для преподавателя

Важное на май 2026: старый пакет @supabase/auth-helpers-nextjs deprecated, актуальный — @supabase/ssr. Также Supabase ввёл новые ключи (sb_publishable_*, sb_secret_*); старые anon/service_role работают до конца 2026, но новые — рекомендуются.

Время: ~10 мин Supabase, ~10 мин OpenAI, ~10 мин health check.

Совет: покажите вживую как Supabase автоматически пишет ваши .env переменные при создании проекта.

1. Создаём проект в Supabase

Supabase — это «облачная база данных + готовая авторизация» в одном флаконе. PostgreSQL под капотом, плюс магик-линки, OAuth, пароли — всё из коробки. Бесплатный план хватает для пет-проектов: 500 МБ, 50 000 пользователей.

Шаг 1 — регистрация

  1. Зайдите на supabase.com → Start your project
  2. Войдите через GitHub
  3. Создайте новую организацию (бесплатный «Free» план)

Шаг 2 — создать проект

  1. Нажмите New project
  2. Имя: mood-tracker
  3. Database password — придумайте сильный, сохраните в менеджере паролей
  4. Region: ближайший к вам (Frankfurt для Европы, Singapore для Азии)
  5. Нажмите Create new project и подождите 1–2 минуты

Шаг 3 — забрать ключи

В дашборде проекта: Project Settings (шестерёнка) → API. Вам нужны:

Ключ Куда положить Где использовать
Project URL NEXT_PUBLIC_SUPABASE_URL Везде (URL не секретный)
Publishable key (новый, sb_publishable_…) NEXT_PUBLIC_SUPABASE_ANON_KEY Браузер. Ограничен RLS-правилами — безопасно
Secret key (новый, sb_secret_…) SUPABASE_SERVICE_ROLE_KEY Только сервер! Полные права на БД

Откройте .env.local в проекте и впишите:

bash 
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxxx
SUPABASE_SERVICE_ROLE_KEY=sb_secret_xxxxx
Service Role Key — никогда не давайте префикс NEXT_PUBLIC_. Если он попадёт в браузер — любой сможет читать/писать всю вашу базу.

Не забудьте также добавить эти переменные в Vercel → Settings → Environment Variables (урок 5.5).

2. Подключаем @supabase/ssr

В Next.js 16 есть и Server Components (рисуются на сервере), и Client Components (в браузере). Им нужны разные Supabase-клиенты. Пакет @supabase/ssr даёт два готовых конструктора.

Старый пакет @supabase/auth-helpers-nextjs deprecated с 2024 года. Если видите его в туториалах — это устарело. Используем только @supabase/ssr.

Шаг 1 — установить

bash 
npm install @supabase/supabase-js @supabase/ssr

Шаг 2 — клиент для браузера

Создайте файл src/lib/supabase/client.ts:

typescript 
import { createBrowserClient } from '@supabase/ssr';

export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
  );
}

Используется в Client Components (с директивой 'use client'):

tsx 
'use client';
import { createClient } from '@/lib/supabase/client';

const supabase = createClient();
const { data } = await supabase.from('moods').select();

Шаг 3 — клиент для сервера

Создайте файл src/lib/supabase/server.ts:

typescript 
import { createServerClient } from '@supabase/ssr';
import { cookies } from 'next/headers';

export async function createClient() {
  const cookieStore = await cookies();

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll();
        },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options)
            );
          } catch {
            // Server Component — записывать cookies нельзя, обновится через middleware
          }
        },
      },
    }
  );
}

Используется в Server Components и API-роутах:

tsx 
// src/app/dashboard/page.tsx (Server Component)
import { createClient } from '@/lib/supabase/server';

export default async function Dashboard() {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();

  return <h1>Привет, {user?.email}</h1>;
}

Шаг 4 — middleware для обновления сессии

Создайте файл src/middleware.ts в корне src/:

typescript 
import { type NextRequest, NextResponse } from 'next/server';
import { createServerClient } from '@supabase/ssr';

export async function middleware(request: NextRequest) {
  let response = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll();
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value)
          );
          response = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) =>
            response.cookies.set(name, value, options)
          );
        },
      },
    }
  );

  // Обновляем сессию (если access token истёк)
  await supabase.auth.getUser();

  return response;
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};

Этот файл сам обновляет сессию пользователя, чтобы пропавшие куки не выкидывали из аккаунта посреди работы. Можно скопировать как есть и забыть.

Совет: в Cursor скажите: «Сделай structure для Supabase SSR в этом проекте — клиент браузера, клиент сервера и middleware. Ключи в .env.local.» — он создаст эти три файла за раз. Главное — у вас в AGENTS.md прописан стек, и Cursor поймёт.
3. Подключаем OpenAI

Шаг 1 — создать ключ

  1. Заходите на platform.openai.com
  2. Регистрируетесь, заходите в Billing → положите $5 (минимальный депозит для API)
  3. API keys → Create new secret key
  4. Скопируйте ключ sk-proj-... сразу (потом полностью увидеть нельзя)

Добавьте в .env.local:

bash 
OPENAI_API_KEY=sk-proj-xxxxx

Шаг 2 — установить SDK

bash 
npm install openai

Шаг 3 — создать клиент

Создайте файл src/lib/openai.ts:

typescript 
import OpenAI from 'openai';

export const openai = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});

Шаг 4 — пример API-роута

Файл src/app/api/insight/route.ts — запрашивает у ИИ совет по записям настроения:

typescript 
import { openai } from '@/lib/openai';
import { NextResponse } from 'next/server';

export async function POST(request: Request) {
  try {
    const { moods } = await request.json();

    const completion = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages: [
        { role: 'system', content: 'Ты эмпатичный коуч. Отвечай коротко.' },
        { role: 'user', content: `Записи: ${JSON.stringify(moods)}` },
      ],
    });

    return NextResponse.json({
      insight: completion.choices[0].message.content,
    });
  } catch (error) {
    return NextResponse.json(
      { error: 'OpenAI запрос упал' },
      { status: 500 }
    );
  }
}

Какую модель выбирать (май 2026)

Модель Когда использовать Цена
gpt-4o-mini Стандарт для простых задач (тексты, классификация) Очень дёшево
gpt-5 Сложные рассуждения, многошаговая логика Средне
o4-mini Когда нужны цепочки рассуждений Средне

Для MoodTracker и большинства учебных проектов — gpt-4o-mini. Хватает с запасом.

4. Health check — проверяем, что всё работает

«Health check» — простая страница или endpoint, которая возвращает «ОК», если все сервисы доступны. Удобно проверять перед демо и после деплоя.

Создайте файл src/app/api/health/route.ts:

typescript 
import { createClient } from '@/lib/supabase/server';
import { openai } from '@/lib/openai';
import { NextResponse } from 'next/server';

export async function GET() {
  const checks = {
    supabase: false,
    openai: false,
    timestamp: new Date().toISOString(),
  };

  // Проверка Supabase
  try {
    const supabase = await createClient();
    const { error } = await supabase.auth.getSession();
    checks.supabase = !error;
  } catch {
    checks.supabase = false;
  }

  // Проверка OpenAI
  try {
    const models = await openai.models.list();
    checks.openai = models.data.length > 0;
  } catch {
    checks.openai = false;
  }

  const allHealthy = checks.supabase && checks.openai;

  return NextResponse.json(checks, {
    status: allHealthy ? 200 : 503,
  });
}

Откройте в браузере: http://localhost:3000/api/health

Если видите {"supabase": true, "openai": true} — поздравляю, оба сервиса подключены. После деплоя на Vercel этот же endpoint будет работать на боевом домене.

Бонус: добавьте Vercel Cron Jobs и пусть Vercel сам пингует /api/health каждые 5 минут — если что-то сломалось, узнаете первыми.
