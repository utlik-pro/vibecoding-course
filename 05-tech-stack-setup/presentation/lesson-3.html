CLAUDE.md и AGENTS.md — память для ИИ

Что вы сделаете:

  • Поймёте разницу между CLAUDE.md, AGENTS.md и правилами Cursor
  • Напишете AGENTS.md — единый файл-инструкцию, который понимают все ИИ-ассистенты
  • Запустите Claude Code в проекте и проверите, что он подхватил контекст
  • Узнаете, как обновлять файл по мере роста проекта
Заметка для преподавателя

Главная мысль урока: на май 2026 индустрия пришла к единому формату инструкций для ИИ-агентов — это AGENTS.md. Его читают Claude Code, Codex, Cursor, Aider и другие. CLAUDE.md — частный случай для Claude Code; если у вас уже есть AGENTS.md — Claude его прочитает.

Время: ~5 мин концепция, ~10 мин писать AGENTS.md, ~10 мин запуск Claude Code, ~5 мин обновление файла.

Покажите вживую: запустите claude в папке без AGENTS.md и с ним — разница в качестве ответов огромная.

1. Зачем ИИ нужен файл-инструкция

Когда вы пишете в Composer Cursor или в чате Claude Code запрос — ИИ не знает ничего про ваш проект. Он видит только то, что у вас сейчас открыто. Каждый раз начинать с «у меня Next.js 16, TypeScript, Supabase…» — нудно и быстро забывается.

Решение — файл-инструкция в корне проекта. ИИ читает его автоматически перед каждым запросом и сразу понимает контекст.

Три «диалекта» одной идеи

На май 2026 в индустрии есть три файла, которые делают одно и то же. Не пугайтесь — выбирать не придётся.

Файл Кто читает Когда использовать
AGENTS.md Claude Code, Codex, Cursor, Aider — все современные ИИ По умолчанию. Универсальный стандарт 2026
CLAUDE.md Только Claude Code Если нужны инструкции специально для Claude (например, упомянуть его имя)
.cursor/rules/*.mdc Только Cursor Если у Cursor должны быть особые правила (мы делали в уроке 5.2)
Что делать новичку: пишите один AGENTS.md. Этого достаточно. Если позже понадобятся специфичные настройки для Claude — добавите CLAUDE.md поверх.
Если вы создавали проект через create-next-app в уроке 5.1 и согласились на «recommended defaults» — AGENTS.md уже есть в корне. Его осталось только наполнить.
2. Пишем AGENTS.md для MoodTracker

Откройте AGENTS.md в корне проекта. Если его нет — создайте: touch AGENTS.md. Замените содержимое на это:

markdown 
# MoodTracker

## О проекте
Веб-приложение, где пользователь раз в день отмечает настроение
от 1 до 5 и пишет короткую заметку. На дашборде — график за 30 дней.
Раз в неделю ИИ-помощник анализирует записи и пишет совет.

## Технический стек
- Next.js 16 + App Router
- TypeScript (strict mode)
- Tailwind CSS 4
- shadcn/ui для UI-компонентов
- Supabase (Auth + Postgres)
- OpenAI API (модель gpt-4o-mini для инсайтов)
- Vercel для хостинга

## Структура папок
src/
├── app/              ← страницы и API-роуты Next.js
│   ├── (auth)/       ← страницы логина и регистрации
│   ├── (dashboard)/  ← защищённые страницы после входа
│   └── api/          ← бэкенд-роуты
├── components/       ← React-компоненты
│   └── ui/           ← готовые компоненты shadcn/ui
├── lib/              ← вспомогательные функции
│   ├── supabase/     ← клиенты Supabase для браузера и сервера
│   └── openai.ts     ← клиент OpenAI
└── types/            ← общие TypeScript-типы

## Правила
- Server Components по умолчанию. "use client" — только если нужны useState, useEffect, обработчики событий.
- Все формы валидируем через zod.
- Ошибки в API-роутах — try/catch, возвращаем { error: string } со статусом 4xx или 5xx.
- Никаких "any" в TypeScript — пиши настоящие типы или { unknown } + проверки.
- Секреты только через переменные окружения (process.env.X). Никогда не хардкодить.

## Как запускать
- `npm run dev` — локальный сервер на localhost:3000
- `npm run build` — production-сборка (запускайте перед деплоем)
- `npm run lint` — проверка кода ESLint

## Важные файлы
- src/lib/supabase/server.ts — клиент Supabase для серверных компонентов
- src/lib/supabase/client.ts — клиент Supabase для браузера
- src/middleware.ts — обновление сессии Supabase

## Чего НЕ делать
- Не использовать Pages Router (только App Router)
- Не вызывать Supabase Service Role Key из браузера
- Не возвращать "any" из API-роутов
Длина файла: 1–2 экрана идеально. Если AGENTS.md разрастается до простыни — ИИ начинает «теряться». Лучше короткий и точный, чем огромный и расплывчатый.

Что должно быть в файле — и почему

📋 О проекте — одна-две фразы

Не пишите «MoodTracker — это инновационная платформа…». Пишите как другу: «Сайт, где пользователь отмечает настроение». ИИ нужен контекст, а не маркетинг.

🛠️ Стек — конкретные версии

Не «Next.js», а «Next.js 16». В Next.js 16 поведение другое, чем в 14. ИИ может предложить устаревший синтаксис, если не знает версию.

📁 Структура папок

Без этого ИИ может создать файл «по своим понятиям» — например, в app/components, когда у вас всё в src/components. Дерево из 5–10 строк решает проблему.

✅ Правила — что соблюдать всегда

5–10 коротких пунктов, не больше. Это «то, что вы повторяли бы новому разработчику в команде». Например: «Все формы — через zod». Если правил много — приоритизируйте.

🚫 Чего НЕ делать

Запреты эффективнее разрешений. Вместо «всегда используй App Router» пишите «не используй Pages Router». Психологически модели лучше реагируют на чёткие границы.

3. Запускаем Claude Code в проекте

Claude Code — это утилита от Anthropic, которая работает прямо из терминала. В отличие от Cursor (это редактор), Claude Code — это «коллега» в командной строке: вы говорите на русском или английском, он редактирует файлы, запускает команды, читает ошибки.

Шаг 1 — установить

bash 
npm install -g @anthropic-ai/claude-code

Подходит для Mac, Windows и Linux. Для работы нужна подписка на claude.ai (или ANTHROPIC_API_KEY).

Шаг 2 — запустить в папке проекта

bash 
cd mood-tracker
claude

Откроется интерактивная сессия в терминале. Claude Code автоматически прочтёт ваш AGENTS.md и поймёт проект.

Шаг 3 — попробовать

Напишите в сессии (на русском!):

claude 
Покажи структуру проекта и расскажи, что уже сделано

Claude посмотрит файлы и расскажет. Дальше можно давать настоящие задачи:

claude 
Создай страницу /login с формой email и кнопкой "Войти".
Используй shadcn/ui. Submit пока пусть просто выводит email в console.log.

Claude создаст файлы, покажет, что сделал, и спросит подтверждения перед каждым действием. Если ошибётся — сами скажете «исправь, у меня вылазит ошибка X» — он попробует ещё раз.

Cursor vs Claude Code: Cursor лучше для «писать код в редакторе». Claude Code лучше для «сделай мне сразу несколько файлов и запусти команды». Часто они дополняют друг друга.

Полезные команды внутри Claude Code

  • /clear — стереть текущий контекст разговора (когда переключаетесь на новую задачу)
  • /help — справка по командам
  • /init — Claude сам сгенерирует CLAUDE.md на основе вашего кода (хорошая отправная точка)
  • Ctrl+C — выйти
4. Как поддерживать AGENTS.md живым

Самая частая ошибка — написать файл один раз и забыть. Через месяц проект уехал, файл устарел, ИИ предлагает странные вещи.

Когда обновлять

  • Добавили новую библиотеку — впишите её в «Стек»
  • Завели новую папку — обновите дерево
  • Поняли, что ИИ повторяет одну и ту же ошибку — добавьте правило
  • Меняете подход (например, переходите с REST на tRPC) — отразите

Удобный приём — попросите ИИ обновить файл

В Claude Code или Cursor:

prompt 
Посмотри текущий код проекта и обнови AGENTS.md:
актуализируй стек, структуру папок и правила.
Сохрани разделы как есть, не добавляй новых.

ИИ сам сравнит файл с реальностью и предложит правки — вам останется только их прочитать и принять.

Не клейте секреты в AGENTS.md. Файл коммитится в Git, его видят все коллеги (и ИИ). Никаких ключей API, паролей, ссылок на личные дашборды. Только публичная архитектура и правила.
