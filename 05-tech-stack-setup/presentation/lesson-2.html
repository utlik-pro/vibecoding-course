Настраиваем Cursor — он будет писать код за вас

Что вы сделаете:

  • Поймёте, чем Cursor отличается от обычного редактора (и зачем он вообще)
  • Создадите файл-инструкцию для ИИ внутри проекта (.cursor/rules/)
  • Освоите два главных режима: Tab (автодополнение) и Composer (диалог)
  • Включите Memories — Cursor будет помнить ваши предпочтения между проектами
Заметка для преподавателя

Версия Cursor на май 2026: 1.x. В новой версии правила переехали из .cursorrules (одинокий файл) в папку .cursor/rules/ с несколькими файлами по темам. Старый формат тоже работает, но новичкам лучше сразу учить актуальный.

Время: ~3 мин что такое Cursor, ~10 мин правила, ~10 мин Composer/Tab, ~5 мин Memories, ~2 мин чек-лист.

Совет: Покажите разницу «с правилами» vs «без правил» на одном промпте. Без правил Cursor пишет «общий React», с правилами — соблюдает ваш стек.

1. Что такое Cursor (и почему не VS Code)

Cursor — это редактор кода, в который встроен ИИ-помощник. Внешне он выглядит как VS Code (потому что сделан на его основе), но внутри есть две суперспособности:

⌨️

Tab — допишет за вас

Начали писать строчку — ИИ предлагает продолжение, нажмите Tab и оно вставится. Как T9 в смартфоне, только умнее.

💬

Composer — общается

Нажали ⌘+I (Mac) или Ctrl+I (Windows) — открылся чат, где можно сказать «сделай мне страницу логина» и ИИ её сделает.

🧠

Memories — помнит вас

Запоминает ваши предпочтения между разговорами: «всегда Tailwind», «не люблю классовые компоненты». В Cursor 1.0+ работает по умолчанию.

🤖

Background Agent

Большие задачи отправляете в фон — Cursor работает в облаке, пока вы пьёте кофе. Возвращается с готовыми изменениями.

Установка: cursor.com → «Download». Бесплатный план — 50 ИИ-запросов в день. Pro (~$20/мес) — без лимитов и доступ к лучшим моделям. Для учёбы хватает бесплатного.
2. Правила проекта — главная настройка

Самое важное, что вы сделаете в этом уроке — научите Cursor понимать ваш конкретный проект. Без этого ИИ будет писать «среднеабстрактный React», который не вписывается в ваш стек.

В Cursor 1.x правила лежат в папке .cursor/rules/ в корне проекта. Каждый файл — про одну тему.

Заметка для преподавателя
Старый формат — одинокий файл .cursorrules в корне — тоже работает, для совместимости. Если в проекте уже есть такой файл, Cursor его прочитает. Но в новых проектах используйте .cursor/rules/.

Шаг 1 — создать папку и файл

В терминале (находясь в корне вашего проекта) выполните:

bash 
mkdir -p .cursor/rules
touch .cursor/rules/project.mdc

.mdc — это формат правил Cursor (MDC = «Markdown с метаданными»). Внешне почти как обычный .md.

Шаг 2 — описать проект

Откройте .cursor/rules/project.mdc и вставьте:

markdown 
---
description: Главные правила проекта MoodTracker
alwaysApply: true
---

# Контекст
Это веб-приложение MoodTracker — пользователь раз в день
отмечает настроение от 1 до 5 и пишет короткую заметку.

# Стек
- Next.js 16 (App Router)
- TypeScript (строгий режим)
- Tailwind CSS v4
- shadcn/ui компоненты
- Supabase (база и авторизация)
- Vercel (деплой)

# Стиль кода
- Server Components по умолчанию, "use client" только если нужна интерактивность
- Маленькие файлы: один компонент = один файл
- Имена компонентов с большой буквы: UserCard.tsx
- Утилиты с маленькой: formatDate.ts
- Используй уже готовые компоненты из src/components/ui/

# Правила безопасности
- Никогда не хардкодь API ключи и секреты — только через переменные окружения
- Все ошибки оборачивай в try/catch
- Никаких 'any' в TypeScript — пиши настоящие типы

# Чего НЕ делать
- Не использовать Pages Router (только App Router)
- Не пропускать TypeScript типы
- Не создавать компоненты без типизации

Шаг 3 — проверить, что Cursor увидел

Откройте Composer (⌘+I / Ctrl+I), напишите: «Какой стек у этого проекта?». Если Cursor отвечает по вашему файлу правил — всё работает.

alwaysApply: true в шапке файла означает «применять эти правила к каждому запросу». Без этой строчки Cursor подключает правила только когда сам считает нужным — для критических вещей лучше принудительно.

Что значит каждая секция в правилах

📋 Контекст

Одно предложение: что строим и для кого. ИИ сразу понимает контекст. Не пишите эссе — двух-трёх строк достаточно.

🛠️ Стек

Список ваших технологий. Без этого Cursor может предложить React Router вместо App Router или CSS Modules вместо Tailwind.

🎨 Стиль кода

Как вы хотите, чтобы выглядел код. Имена файлов, размер компонентов, какие компоненты использовать «из коробки». Из-за этого Cursor создаст файл UserCard.tsx, а не userCard.tsx — мелочь, но в проекте всё единообразно.

🚫 Чего НЕ делать

Запреты работают сильнее, чем разрешения. «Не используй Pages Router» лучше, чем «используй App Router» — ИИ точно не сорвётся в старый стиль.

3. Tab и Composer — два режима работы

Tab — для маленьких подсказок

Просто пишете код, Cursor предлагает продолжение серым текстом. Нажали Tab — вставилось. Не нравится — пишете дальше, ИИ переподумает.

Что хорошо подходит для Tab:

  • Дописать поля у объекта
  • Закрыть JSX-тег
  • Дописать функцию по её сигнатуре
  • Поставить недостающий импорт

Composer — для больших задач

Открывается по ⌘+I (Mac) или Ctrl+I (Windows). Это диалог с ИИ, в котором он может:

  • Создавать новые файлы
  • Менять несколько файлов сразу
  • Запускать команды в терминале (с вашего разрешения)
  • Читать ошибки браузера и исправлять их

Пример хорошего промпта в Composer

prompt 
Сделай страницу /login с формой email + пароль.

Требования:
- Использовать shadcn/ui Card, Input, Button
- Поля валидировать через zod
- При сабмите вызывать функцию login(email, password) — заглушку
- Показывать ошибку под формой, если login упал

Файл создать в src/app/login/page.tsx
Главное правило промптов: один промпт = одна понятная задача. Не пишите «сделай весь сайт» — пишите «сделай страницу логина». В уроке 5.6 разберём шаблоны промптов подробнее.

Чем чат отличается от Composer?

В Cursor есть два разных окна для разговора с ИИ — у новичков они путаются:

Режим Что умеет Когда использовать
Чат (⌘+L) Только отвечает текстом, файлы не меняет «Объясни, что делает этот код»
Composer (⌘+I) Меняет файлы, создаёт новые, запускает команды «Сделай страницу логина»
4. Memories — Cursor запоминает ваши привычки

В Cursor 1.0+ появилась штука под названием Memories. Это «долгая память» — между разными разговорами и даже разными проектами Cursor помнит ваши предпочтения.

Например, после нескольких сессий он сам запомнит:

  • «Этот пользователь всегда работает с Tailwind, а не с обычным CSS»
  • «Когда нужно валидировать формы — этот пользователь предпочитает zod»
  • «Этот пользователь не любит классовые компоненты»

Как включить

Settings (⌘+,) → Cursor → Memories → переключатель в положение «On». На большинстве установок включено по умолчанию.

Как добавить запись вручную

В Composer напишите: «Запомни: я всегда использую Tailwind, не пиши мне обычный CSS». Cursor предложит сохранить в Memories. Подтвердите.

Где посмотреть/удалить

Settings → Memories — там список всех запомненных фактов. Можно удалить лишнее.

Memories vs правила проекта: правила в .cursor/rules/ касаются проекта (стек, стиль кода). Memories касаются вас лично: ваши предпочтения, которые работают везде. Не путайте.
5. Полезные настройки на старте
Какую модель выбрать

В правом нижнем углу Composer — выпадающий список моделей. На май 2026:

  • Claude Sonnet 4.6 — лучшая для кода, рекомендую по умолчанию
  • GPT-5 — альтернатива от OpenAI, сильна в логике
  • Auto — Cursor сам выбирает под задачу. Удобно для простых вещей.
Codebase Indexing — индексация проекта

Settings → Features → Codebase Indexing → Enable. Cursor «прочитает» весь ваш проект и будет учитывать его при ответах. Без этого ИИ видит только открытый файл.

Auto-Run — давать команды в терминале

В Cursor 1.x можно разрешить ИИ выполнять безопасные команды (npm install, git status) без вашего подтверждения каждый раз. Settings → Features → Auto-Run.

Безопасность: опасные команды (rm -rf, git push --force) всё равно требуют подтверждения. Но первое время лучше держите Auto-Run выключенным — посмотрите, что Cursor хочет запускать.

AGENTS.md — Cursor читает его автоматически

Если в корне проекта лежит файл AGENTS.md (создаётся при create-next-app в Next.js 16), Cursor его читает наравне с правилами в .cursor/rules/. Это новый кросс-инструментальный стандарт — тот же файл понимают Claude Code, Codex и другие ИИ-агенты. Подробно про AGENTS.md — в уроке 5.3.
