Настройка Cursor

Цели урока:

  • Создать .cursorrules файл для проекта
  • Настроить Composer Rules
  • Понять best practices для работы с Cursor
Заметка для преподавателя

Важно: Покажите, как правильно настроенный .cursorrules файл влияет на качество генерации кода. Сравните результаты с файлом и без него.

1. Что такое .cursorrules

.cursorrules — это файл настроек для ИИ-помощника в Cursor IDE. Он определяет:

  • Контекст проекта — какой стек технологий используется
  • Стиль кода — какие паттерны и конвенции соблюдать
  • Правила генерации — как ИИ должен писать код
  • Ограничения — чего ИИ должен избегать
Почему это важно: Без .cursorrules ИИ генерирует "общий" код. С правильными настройками — код, который соответствует вашему проекту.
2. Создание .cursorrules файла

Создайте файл .cursorrules в корне проекта:

markdown 
# Project Context

This is a Next.js 14+ SaaS application.

## Tech Stack
- Next.js 14 with App Router
- TypeScript with strict mode
- Tailwind CSS for styling
- shadcn/ui components
- Supabase for database and auth
- Vercel for hosting

## Code Style

### Components
- Use functional components with TypeScript
- Prefer Server Components by default
- Add 'use client' only when necessary (interactivity, hooks)
- Keep components small and focused (single responsibility)

### File Structure
- Components: src/components/
- API routes: src/app/api/
- Utilities: src/lib/
- Types: src/types/

### Naming Conventions
- Components: PascalCase (UserCard.tsx)
- Utilities: camelCase (formatDate.ts)
- Types: PascalCase with 'I' prefix for interfaces (IUser)

## Important Rules

1. Always handle errors with try/catch
2. Use environment variables for secrets (never hardcode)
3. Write type-safe code (avoid 'any')
4. Use existing shadcn/ui components from src/components/ui/
5. Follow Next.js 14 conventions (app router, server actions)

## Do NOT
- Use Pages Router (only App Router)
- Skip TypeScript types
- Hardcode API keys or secrets
- Create components without proper types

Разбор каждой секции:

📋 Project Context — Контекст проекта

Что это: Краткое описание проекта в одной строке.

Зачем нужно: ИИ сразу понимает тип приложения и его масштаб. "SaaS application" говорит о том, что это коммерческий продукт с пользователями, подписками, аутентификацией.

Примеры:

  • This is a Next.js 14+ SaaS application.
  • This is a portfolio website for a designer.
  • This is an e-commerce platform for digital products.
🛠️ Tech Stack — Технологический стек

Что это: Список всех технологий, библиотек и сервисов в проекте.

Зачем нужно: ИИ будет использовать только эти технологии. Без этого списка он может предложить React вместо Next.js, или CSS вместо Tailwind.

Что включать:

  • Фреймворк: Next.js 14, React 18, Vue 3
  • Язык: TypeScript с режимом (strict mode)
  • Стилизация: Tailwind CSS, CSS Modules, Styled Components
  • UI-библиотека: shadcn/ui, MUI, Chakra
  • Backend/БД: Supabase, Firebase, Prisma
  • Хостинг: Vercel, Netlify, AWS
🎨 Code Style — Стиль кода

Что это: Правила написания кода — как именовать файлы, как структурировать компоненты.

Зачем нужно: Код от ИИ будет консистентным с вашим проектом. Без этого ИИ может создать файл user-card.tsx когда у вас везде UserCard.tsx.

Что указывать:

  • Components: Функциональные vs классовые, Server vs Client Components
  • File Structure: Где лежат компоненты, утилиты, типы
  • Naming: PascalCase, camelCase, kebab-case для разных типов файлов
✅ Important Rules — Важные правила

Что это: Обязательные правила, которые ИИ должен соблюдать всегда.

Зачем нужно: Предотвращает типичные ошибки. ИИ может "забыть" обработать ошибку или захардкодить API ключ.

Типичные правила:

  • Error handling: Всегда оборачивать в try/catch
  • Security: Использовать env variables для секретов
  • Types: Избегать any, писать типы
  • Patterns: Использовать существующие компоненты
🚫 Do NOT — Запреты

Что это: Явный список того, что ИИ НЕ должен делать.

Зачем нужно: Негативные инструкции работают лучше позитивных. "Не используй Pages Router" эффективнее чем "используй App Router".

Типичные запреты:

  • Не использовать устаревшие паттерны (Pages Router)
  • Не пропускать типы TypeScript
  • Не хардкодить секреты
  • Не создавать компоненты без типов
  • Не использовать any
3. Composer Rules

Composer — это режим в Cursor для создания/редактирования нескольких файлов одновременно (Cmd/Ctrl + I). В отличие от обычного чата, Composer может:

  • Создавать новые файлы
  • Редактировать существующие файлы
  • Работать с несколькими файлами за один запрос

Добавьте инструкции для Composer в .cursorrules:

markdown 
## Composer Guidelines

When creating new features:
1. Create component file in src/components/
2. Add types to src/types/ if needed
3. Create API route in src/app/api/ if needed
4. Update existing components to use the new feature

When fixing bugs:
1. Identify the root cause first
2. Fix the specific issue without refactoring
3. Add error handling if missing
4. Test the fix before completing

When refactoring:
1. Keep the same functionality
2. Improve code readability
3. Add missing types
4. Follow existing patterns in the codebase

Разбор Composer Guidelines:

🆕 When creating new features — Создание фичи

Что это: Пошаговая инструкция для ИИ, когда вы просите создать новую функциональность.

Зачем нужно: Без этого ИИ может создать всё в одном файле или положить компоненты не туда. С инструкцией он следует вашей структуре проекта.

Пример запроса: "Создай форму регистрации пользователя"

ИИ сделает:

  1. src/components/SignUpForm.tsx — компонент формы
  2. src/types/auth.ts — типы для формы
  3. src/app/api/auth/signup/route.ts — API endpoint
  4. Обновит страницу, где используется форма
🐛 When fixing bugs — Исправление багов

Что это: Правила поведения ИИ при исправлении ошибок.

Зачем нужно: Без этого ИИ может "переписать всё" вместо точечного фикса. Или добавить кучу нового кода вместо исправления одной строки.

Ключевые моменты:

  • Найти причину — не просто убрать симптом
  • Минимальные изменения — не рефакторить попутно
  • Добавить защиту — error handling если его не было
♻️ When refactoring — Рефакторинг

Что это: Правила для улучшения кода без изменения функциональности.

Зачем нужно: ИИ может "улучшить" код так, что он перестанет работать. Эти правила гарантируют, что рефакторинг безопасен.

Принципы:

  • Сохранить поведение — код должен работать так же
  • Улучшить читаемость — понятные имена, структура
  • Добавить типы — если были пропущены
  • Следовать паттернам — как уже сделано в проекте
Совет: Добавьте свои сценарии! Например: "When adding a new page", "When creating a hook", "When adding tests".
4. Настройки редактора

Рекомендуемые настройки Cursor для Next.js проектов:

Tab Completion

Включите автодополнение по Tab:

  • Settings > Cursor Tab > Enable
  • Позволяет принимать предложения ИИ по Tab
Model Selection

Выберите модель для генерации:

  • Claude 3.5 Sonnet — рекомендуется для кода
  • GPT-4 — альтернатива
Codebase Indexing

Индексация проекта улучшает контекст:

  • Settings > Features > Codebase Indexing > Enable
  • Cursor будет учитывать весь код проекта
