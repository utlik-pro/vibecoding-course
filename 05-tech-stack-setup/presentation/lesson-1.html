Создаём первый Next.js проект

Что вы сделаете:

  • Сначала «договоритесь» с ИИ о том, что строите (план = меньше переделок)
  • Одной командой создадите готовый шаблон сайта (Next.js)
  • Посмотрите, какие папки и файлы появились — и что в них
  • Запустите сайт у себя на ноутбуке и откроете в браузере
Заметка для преподавателя

Время на секции: ~7 мин план с ИИ, ~3 мин что такое Next.js, ~10 мин создание, ~7 мин структура, ~3 мин запуск.

Стек на май 2026: Next.js 16, React 19, Tailwind CSS 4. Промпты create-next-app в этой версии другие — не как в старых туториалах. Не давайте студентам гуглить «как создать Next.js» в момент урока.

Частая проблема: у кого-то Node.js старше 20 — Next.js 16 требует Node 20+. Проверьте у всех: node --version должен показывать 20.x или 22.x.

Совет: выполняйте команды одновременно со студентами, после каждого шага — пауза «у всех получилось?».

0. Сначала договариваемся с ИИ — что строим

Главная ошибка новичка — сразу открыть редактор и начать писать. ИИ сделает что-то, потом вы поймёте, что хотели по-другому, и придётся переделывать. Сильно дешевле потратить 15 минут на разговор с ИИ до кода.

Откройте claude.ai или chatgpt.com и просто опишите, что хотите. Шаблон промпта ниже.

Зачем: ответ ИИ станет вашим черновиком плана. Дальше из него родятся PRD (урок 5.4), CLAUDE.md (урок 5.3) и .cursorrules (урок 5.2) — мы будем переиспользовать его.

1. Что такое Next.js (простыми словами)

Next.js — это «коробка с готовыми инструментами», чтобы делать сайты. Внутри уже лежат все основные кубики: страницы, картинки, формы, кнопки — нужно только сложить их так, как вам нужно.

Если бы Next.js не было — пришлось бы вручную собирать каждый кусочек: настраивать сервер, маршруты, картинки, шрифты. С Next.js всё это уже сделано за вас. Вы просто описываете, как должны выглядеть страницы — а Next.js делает остальное.

Что вы получаете «из коробки»

📄

Страницы из папок

Сделали папку about — появилась страница /about. Никаких дополнительных настроек.

⚡

Быстрый сайт

Картинки, шрифты, скрипты автоматически оптимизируются — сайт грузится быстро.

🔌

Сервер прямо здесь

Можно делать «бэкенд» (логика на сервере) в той же папке — не нужно поднимать отдельный сервис.

🤖

Дружит с ИИ

Cursor и Claude Code знают Next.js «вдоль и поперёк» — генерируют код, который реально работает.

На май 2026 актуальна Next.js 16 — мы будем использовать именно её. Она быстрее предыдущих версий и сама оптимизирует ваш код через React Compiler (это новая «волшебная» штука, о которой не нужно думать — она просто работает).
🤓 Если встретите эти термины — вот что они значат
  • React — «движок», на котором работает Next.js. Можно сравнить: React = двигатель, Next.js = вся машина с рулём, сиденьями и стеклоочистителями.
  • App Router — способ, которым Next.js делает страницы из папок. В этом курсе всегда используем именно его (он современный).
  • Server Components — компоненты, которые «рисуются» на сервере, а не в браузере пользователя. Сайт открывается быстрее. По умолчанию в Next.js 16 все компоненты такие — пока не помечено иначе.
  • TypeScript — это JavaScript с подсказками о типах. Когда напишете let age: number = 25, редактор будет ругаться, если вы случайно положите туда строку. Меньше багов.
  • Production-ready — «готовое к запуску в реальный мир» (а не только для учёбы).
2. Одна команда — и проект готов
Заметка для преподавателя
В Next.js 16 промпты при создании сильно изменились — есть быстрый путь «recommended defaults» (один Yes на всё). Покажите его, потом расскажите, что было бы при customize.

Шаг 1 — открыть терминал

Терминал — это окошко, где вы пишете команды текстом, а компьютер их выполняет. На Mac: Spotlight (⌘ + пробел) → введите «Terminal» → Enter. На Windows: «Терминал» в меню Пуск.

Зайдите в папку, где хотите создать проект (например, ~/Desktop):

bash 
cd ~/Desktop

Шаг 2 — запустить волшебную команду

Эта команда скачает и развернёт готовый шаблон сайта:

bash 
npx create-next-app@latest mood-tracker

mood-tracker — это имя папки, в которой создастся проект. Можно назвать как угодно, главное — без пробелов и кириллицы.

Шаг 3 — ответить на вопросы

CLI (то самое окошко терминала) задаст несколько вопросов. В Next.js 16 первый вопрос — самый важный:

«Would you like to use the recommended Next.js defaults?»
Ответ: Yes. Этого достаточно — Next.js сам поставит TypeScript, ESLint, Tailwind CSS, App Router и AGENTS.md (файл подсказок для ИИ). Можно прыгать сразу к шагу 4.

Если хочется выбрать всё вручную (No → customize)

Тогда CLI задаст серию вопросов. Вот рекомендованные ответы для нашего курса:

Вопрос Ответ Почему
Would you like to use TypeScript? Yes Редактор будет подсказывать ошибки до запуска
Which linter would you like to use? (ESLint / Biome / None) ESLint Самый известный, ИИ его знает наизусть
Would you like to use React Compiler? Yes Автоматически ускоряет ваш сайт. Бесплатно, не требует настройки
Would you like to use Tailwind CSS? Yes Стилизация классами, быстро и без отдельных CSS-файлов
Would you like your code inside a src/ directory? Yes Весь код в одной папке — чище
Would you like to use App Router? Yes Современный способ делать страницы (старый — только для legacy)
Would you like to customize the import alias? Yes — оставить @/* Удобный «короткий путь» к файлам внутри проекта
Would you like to include AGENTS.md? Yes Файл с подсказками для Cursor/Claude Code/любого ИИ. Подробно — в уроке 5.3

Шаг 4 — подождать минуту

CLI скачает все зависимости (это слово значит «все нужные библиотеки кода»). Увидите бегущие строчки — это нормально. В конце появится сообщение «Success!» — значит готово.

🤓 Что такое npx, npm, package.json и зависимости
  • npm (Node Package Manager) — «магазин» библиотек кода. Когда мы пишем npm install, мы оттуда скачиваем нужные пакеты.
  • npx — запустить программу из npm один раз, не устанавливая её к себе насовсем. Удобно для команд типа create-next-app.
  • package.json — файл-список того, что использует ваш проект. Как продуктовый список перед походом в магазин.
  • Зависимости — это и есть «продукты», которые ваш проект «покупает» через npm. Они лежат в папке node_modules/ (туда никогда не нужно лезть руками — она огромная).
3. Что внутри проекта — экскурсия

Откройте созданную папку (cd mood-tracker в терминале или через Finder/Проводник). Вот что вы увидите:

Структура 
mood-tracker/
├── src/
│   └── app/
│       ├── layout.tsx      ← общий каркас всех страниц (шапка, подвал)
│       ├── page.tsx        ← главная страница (открывается на "/")
│       ├── globals.css     ← общие стили на весь сайт
│       └── favicon.ico     ← иконка во вкладке браузера
├── public/                  ← сюда кладут картинки, иконки, статику
├── AGENTS.md                ← подсказки для ИИ-ассистентов (Cursor, Claude)
├── package.json             ← список зависимостей, как продуктовая корзина
├── tsconfig.json            ← настройки TypeScript
├── next.config.ts           ← настройки Next.js
└── eslint.config.mjs        ← правила проверки кода
Запомните одно главное правило: 95% вашей работы — внутри папки src/app/. Остальное Next.js настроил за вас, туда лезть почти никогда не понадобится.

Что такое AGENTS.md (новинка Next.js 16)

AGENTS.md — это текстовый файл с подсказками для ИИ-помощников: «вот наш стек, вот правила, делай так-то». Cursor, Claude Code, ChatGPT и другие читают этот файл и пишут код, который вписывается в ваш проект, а не «общий».

Подробно настроим его в уроке 5.3. Пока просто знаете, что он есть.

📁 src/app/ — главное место, где вы работаете

Простое правило: каждая папка внутри app/ — это адрес страницы.

  • app/page.tsx → главная страница сайта (/)
  • app/about/page.tsx → страница «О нас» (/about)
  • app/dashboard/settings/page.tsx → /dashboard/settings

Хотите страницу настроек? Создайте папку settings, в ней файл page.tsx — всё. Никаких роутеров настраивать не нужно.

Специальные имена файлов (важно знать):

  • page.tsx — что показать на этой странице
  • layout.tsx — общий «каркас» (шапка/подвал) для страниц этой папки
  • loading.tsx — что показывать, пока страница грузится
  • error.tsx — что показать, если что-то сломалось
📄 page.tsx — что видит пользователь

Откройте src/app/page.tsx — это главная страница вашего сайта. Внутри что-то такое:

tsx 
export default function Home() {
  return (
    <main className="flex min-h-screen items-center justify-center">
      <h1 className="text-4xl font-bold">Привет, мир!</h1>
    </main>
  );
}

«Перевод» того, что здесь происходит:

  • function Home() — это «функция-страница». Возвращает то, что увидит пользователь.
  • return (...) — возвращаем кусок HTML.
  • className="..." — стили из Tailwind. text-4xl = «большой шрифт», font-bold = «жирный», flex items-center justify-center = «по центру экрана».

Попробуйте поменять «Привет, мир!» на что-то своё, сохраните файл — браузер сам обновится.

📄 layout.tsx — общая обёртка

Файл, который оборачивает все страницы. Сюда обычно кладут шапку, подвал, подключение шрифтов. Пока он есть — но менять его не надо.

Когда понадобится — попросите Cursor: «добавь в layout шапку с логотипом и навигацией» — он сам всё сделает правильно.
4. Запускаем сайт у себя

Зайдите в созданную папку и запустите «локальный сервер» — это значит, ваш ноутбук временно станет хостингом для сайта (только для вас, никто другой не увидит):

bash 
cd mood-tracker
npm run dev

Через 2–3 секунды в терминале появится сообщение «Ready in XXX ms». Откройте в браузере: http://localhost:3000 — увидите свой сайт.

Поздравляем! Вы создали и запустили свой первый Next.js сайт. Это уже больше, чем многие делают.

Попробуйте магию hot reload

Откройте src/app/page.tsx в редакторе, поменяйте текст внутри <h1>...</h1>, сохраните файл (⌘S или Ctrl+S). Браузер обновится автоматически — вы увидите свой текст. Это и называется «hot reload» — горячая перезагрузка.

Команды, которые понадобятся

Команда Что делает Когда использовать
npm run dev Запускает сайт у вас локально Каждый день, когда работаете над проектом
npm run build Собирает «боевую» версию сайта Перед деплоем (урок 5.5) — проверить, что всё компилируется
npm run start Запускает «боевую» версию у вас Редко — обычно «боевая» версия сама работает на Vercel
npm run lint Проверяет код на типичные ошибки Когда что-то странное — стоит запустить
Чтобы остановить сервер — в терминале нажмите Ctrl+C (на Mac тоже именно Ctrl, не Cmd). Сайт перестанет работать на localhost:3000, пока снова не запустите npm run dev.
