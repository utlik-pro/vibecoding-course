Middleware — ваш охранник

Middleware — это код, который выполняется ДО того, как пользователь увидит страницу.

👤

Хочет открыть /dashboard

→
📄

Показывает контент

Middleware работает на сервере! Это значит, что пользователь даже не увидит страницу, если не залогинен — его сразу перенаправит на страницу входа.
Публичные vs Приватные страницы

В любом приложении есть два типа страниц:

Публичные (Public) Приватные (Private)
Доступны всем Только для залогиненных
/ (главная) /dashboard
/about /profile
/login /settings
/register /transactions

Правило простое:

  • Страницы с личными данными = приватные
  • Страницы для всех (маркетинг, вход) = публичные
Код: Создаём src/middleware.ts
Май 2026 — важно: мы используем пакет @supabase/ssr (мы ставили его в модуле 5, урок 5.7). Старый @supabase/auth-helpers-nextjs с функциями createMiddlewareClient, createServerComponentClient — deprecated, в туториалах их больше не используют.

Создайте файл src/middleware.ts. Он делает две вещи: обновляет сессию на каждом запросе и не пускает незалогиненных на приватные страницы.

src/middleware.ts 
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

// Эта функция выполняется ПЕРЕД каждым запросом
export async function middleware(request: NextRequest) {
  // response, который мы можем изменить
  let response = NextResponse.next({ request })

  // Клиент Supabase для middleware (через @supabase/ssr)
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll()
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value)
          )
          response = NextResponse.next({ request })
          cookiesToSet.forEach(({ name, value, options }) =>
            response.cookies.set(name, value, options)
          )
        },
      },
    }
  )

  // ВАЖНО: getUser() обновляет сессию И проверяет токен на сервере.
  // getSession() так не умеет — поэтому в middleware всегда getUser().
  const { data: { user } } = await supabase.auth.getUser()

  const path = request.nextUrl.pathname

  // Список приватных страниц (требуют входа)
  const privateRoutes = ['/dashboard', '/profile', '/settings', '/transactions']
  const isPrivateRoute = privateRoutes.some(route => path.startsWith(route))

  // Приватная страница + не залогинен → на /login
  if (isPrivateRoute && !user) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  // Залогинен и идёт на /login или /register → на /dashboard
  if (user && (path === '/login' || path === '/register')) {
    return NextResponse.redirect(new URL('/dashboard', request.url))
  }

  return response
}

// На каких путях запускать middleware
export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
}
Важно! Файл называется именно middleware.ts и лежит в папке src/ (если у вас структура с src/). Next.js найдёт его автоматически.
Разбираем код по частям

supabase.auth.getUser()

Проверяет, кто сейчас залогинен — и заодно обновляет сессию

Если user = null — пользователь не залогинен. На сервере всегда getUser(), а не getSession(): только getUser() по-настоящему проверяет токен.

privateRoutes.some()

Проверяет, начинается ли путь с одного из приватных маршрутов

Например: /dashboard/settings тоже будет приватным

NextResponse.redirect()

Перенаправляет пользователя на другую страницу

Пользователь даже не увидит приватную страницу — сразу попадёт на /login

config.matcher

Указывает, на каких путях запускать middleware

Мы исключаем статические файлы (картинки, CSS) для скорости

Дополнительная проверка в Server Component

Middleware — это первая линия защиты. Но иногда нужна проверка прямо в компоненте:

Используем серверный клиент src/lib/supabase/server.ts, который мы создали в модуле 5 (урок 5.7):

src/app/dashboard/page.tsx 
import { createClient } from '@/lib/supabase/server'
import { redirect } from 'next/navigation'

// Это Server Component — выполняется на сервере
export default async function DashboardPage() {
  // Серверный клиент Supabase (из @supabase/ssr)
  const supabase = await createClient()

  // Получаем данные текущего пользователя
  const { data: { user } } = await supabase.auth.getUser()

  // Если пользователь не найден — перенаправляем на вход
  if (!user) {
    redirect('/login')
  }

  // Пользователь залогинен — показываем контент
  return (
    <div>
      <h1>Добро пожаловать, {user.email}!</h1>
      <p>Это ваш личный кабинет.</p>

      {/* Здесь будет контент dashboard */}
    </div>
  )
}
@/lib/supabase/server — это файл src/lib/supabase/server.ts с функцией createClient(), внутри которой createServerClient из @supabase/ssr. Один раз написали — переиспользуем везде.
Зачем двойная проверка? Middleware защищает от случайного доступа. Проверка в компоненте — дополнительная страховка и доступ к данным пользователя.
Защита API Routes

Не забываем защитить и API! Иначе хакер может отправить запрос напрямую:

Опасность: Даже если страница защищена, API может быть открыт!

Хакер: curl -X DELETE /api/transactions/123

src/app/api/transactions/route.ts 
import { createClient } from '@/lib/supabase/server'
import { NextResponse } from 'next/server'

// GET — получить транзакции пользователя
export async function GET() {
  const supabase = await createClient()

  // Проверяем авторизацию
  const { data: { user } } = await supabase.auth.getUser()

  // Если не залогинен — возвращаем ошибку 401
  if (!user) {
    return NextResponse.json(
      { error: 'Unauthorized' },
      { status: 401 }  // 401 = не авторизован
    )
  }

  // Получаем транзакции ТОЛЬКО этого пользователя
  const { data: transactions } = await supabase
    .from('transactions')
    .select('*')
    .eq('user_id', user.id)  // Фильтр по user_id!

  return NextResponse.json(transactions)
}

// POST — создать новую транзакцию
export async function POST(request: Request) {
  const supabase = await createClient()

  // Проверяем авторизацию
  const { data: { user } } = await supabase.auth.getUser()

  if (!user) {
    return NextResponse.json(
      { error: 'Unauthorized' },
      { status: 401 }
    )
  }

  // Получаем данные из запроса
  const body = await request.json()

  // Создаём транзакцию С ПРИВЯЗКОЙ к пользователю
  const { data, error } = await supabase
    .from('transactions')
    .insert({
      ...body,
      user_id: user.id  // Берём id из сессии, НЕ из формы!
    })
    .select()

  if (error) {
    return NextResponse.json({ error: error.message }, { status: 400 })
  }

  return NextResponse.json(data)
}
Золотое правило: Всегда проверяйте user в API и используйте user.id для фильтрации данных!

    app/dashboard/page.tsx 
    import { createClient } from '@/lib/supabase/server'
import { redirect } from 'next/navigation'

export default async function DashboardPage() {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()

  if (!user) {
    redirect('/login')
  }

  // Получаем транзакции пользователя
  const { data: transactions } = await supabase
    .from('transactions')
    .select('*')
    .eq('user_id', user.id)

  return (

        {transactions?.length === 0 ? (
          <p>Транзакций пока нет. Добавьте первую!</p>
        ) : (
          <ul>
            {transactions?.map((t) => (
              <li key={t.id} className="py-2 border-b">
                {t.category}: {t.amount} руб.
              </li>
            ))}
          </ul>
        )}
      </div>
    </div>
  )
}

Проверка знаний

Что делает middleware в Next.js?

Создаёт красивый дизайн
Выполняет код ДО показа страницы (проверяет авторизацию)
Сохраняет данные в базу
Отправляет email пользователю

Почему важно защищать API Routes?

Чтобы код работал быстрее
Чтобы страница выглядела красиво
Потому что хакер может отправить запрос напрямую, минуя страницу
API не нужно защищать, только страницы
