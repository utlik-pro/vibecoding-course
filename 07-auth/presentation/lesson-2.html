Как работает Supabase Auth

Supabase Auth — это «готовый охранник из коробки»: не нужно нанимать своего. Разбираемся, что такое сессия и токен, изучаем панель Authentication.

📋 По Task Master: этот урок — теория, конкретных задач не закрываем. Просто понимаем, как устроен Supabase Auth — с урока 7.3 начнём писать код по задачам из task-master list.
Что такое Supabase Auth?

Supabase Auth — это готовая система аутентификации, которая уже встроена в Supabase. Вы уже используете Supabase для базы данных — теперь добавим вход!

Простыми словами: Supabase Auth — это как охранник на входе, который уже нанят и обучен. Вам не нужно его искать и обучать — просто подключаете и работает!

Практика: Смотрим Supabase Dashboard

Задание: Откройте ваш проект в Supabase и найдите раздел Authentication:

  1. Зайдите на supabase.com/dashboard
  2. Откройте ваш проект (Money Tracker)
  3. В левом меню нажмите Authentication

Вы увидите разделы:

  • Users — список зарегистрированных пользователей
  • Policies — правила доступа (кто что может)
  • Providers — способы входа (Email, Google, GitHub)
  • Email Templates — шаблоны писем
  • URL Configuration — настройки ссылок
Сейчас раздел Users пустой — это нормально! Скоро мы добавим первого пользователя.
Провайдеры (способы входа)

Провайдер — это способ, которым пользователь может войти в приложение. Supabase поддерживает много провайдеров:

Провайдер Что это Сложность
Email Классический email + пароль Очень просто
Google Вход через Google аккаунт Средне
GitHub Вход через GitHub аккаунт Средне
Magic Link Ссылка на email вместо пароля Просто
Phone SMS с кодом подтверждения Сложнее (нужен Twilio)
Мы настроим: Email (обязательно) + Google + GitHub. Этого достаточно для большинства проектов!
Как Auth связан с базой данных

Главное преимущество Supabase Auth — автоматическая связь с базой данных:

Как это работает 
1. Пользователь регистрируется
                    ↓
2. Supabase создаёт запись в таблице auth.users
   (это специальная системная таблица)
                    ↓
3. Каждый пользователь получает уникальный ID
   Например: "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
                    ↓
4. Этот ID можно использовать в ВАШИХ таблицах!
   Например: transactions.user_id = auth.uid()

Пример для Money Tracker:

Таблица transactions 
| id | amount | category    | user_id                              |
|----|--------|-------------|--------------------------------------|
| 1  | 50000  | Зарплата    | a1b2c3d4-e5f6-7890-abcd-ef1234567890 | ← Вася
| 2  | -1200  | Кафе        | a1b2c3d4-e5f6-7890-abcd-ef1234567890 | ← Вася
| 3  | 30000  | Фриланс     | x9y8z7w6-v5u4-3210-wxyz-987654321098 | ← Маша
| 4  | -500   | Такси       | x9y8z7w6-v5u4-3210-wxyz-987654321098 | ← Маша
Результат: Теперь Вася видит только свои транзакции, а Маша — только свои!
Основные функции Supabase Auth

Вот функции, которые мы будем использовать:

JavaScript — основные функции 
// Регистрация нового пользователя
supabase.auth.signUp({
  email: 'vasya@mail.ru',
  password: 'secret123'
})

// Вход в систему
supabase.auth.signInWithPassword({
  email: 'vasya@mail.ru',
  password: 'secret123'
})

// Вход через Google
supabase.auth.signInWithOAuth({
  provider: 'google'
})

// Получить текущего пользователя
supabase.auth.getUser()

// Выход из системы
supabase.auth.signOut()
Не пугайтесь кода! Cursor поможет написать всё это. Сейчас просто посмотрите какие функции есть.
RLS — Row Level Security (защита строк)

RLS — это волшебная функция Supabase, которая защищает данные на уровне базы данных.

Сложный термин? Объясняю просто:
RLS = "Каждый видит только свои строки в таблице"
SQL — пример политики RLS 
-- Разрешить пользователям видеть только СВОИ транзакции
CREATE POLICY "Users can view own transactions"
ON transactions
FOR SELECT
USING (user_id = auth.uid());

Что это значит:

  • auth.uid() — это ID текущего пользователя
  • user_id = auth.uid() — показывать только те строки, где user_id совпадает
  • Даже если хакер получит доступ к API — он увидит только свои данные!
RLS — это ваш телохранитель! Он работает автоматически и защищает данные 24/7.
