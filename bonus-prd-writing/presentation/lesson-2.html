Анатомия хорошего PRD

Разбираем полный шаблон PRD по шести секциям. На каждой — пример хорошей и плохой формулировки.

Полный шаблон PRD — 6 секций

Вот скелет, который работает для 90% веб-проектов. На каждую секцию — отдельная карточка ниже с примерами.

markdown — шаблон prd.txt
# [Название проекта] — описание

## О проекте
[1–2 предложения: что строим и для кого]

## Технический стек
- [Фреймворк с версией]
- [Язык]
- [База данных]
- [Хостинг]
- [Дополнительные сервисы]

## Главные функции
### 1. [Название функции]
- [Что делает пользователь]
- [Какие данные вводит]
- [Что видит в ответ]

### 2. [Следующая функция]
...

## Структура базы данных
### Таблица [name]
| Поле | Тип | Обязательное | Описание |

## Этапы разработки
1. [Первый шаг — обычно "настройка"]
2. [...]

## Чего НЕ делаем в этой версии
- [Фичи на потом]
📌 Секция 1: «О проекте»

Цель: в 1–2 предложениях объяснить, что строим. Эти строки увидит ИИ первыми — они задают контекст.

❌ Плохо

«Революционная платформа нового поколения, объединяющая искусственный интеллект и блокчейн для оптимизации пользовательского опыта…»

Куча маркетинга, никакой конкретики. ИИ не знает что делать.

✅ Хорошо

«Сайт, где пользователь записывает доходы и расходы, видит баланс за месяц и удаляет/редактирует старые записи.»

Сразу ясно: что хранится, что делает пользователь, какой scope.

🛠️ Секция 2: «Технический стек»

Цель: явно перечислить технологии с версиями. Без версий ИИ выдаст устаревший синтаксис.

❌ Плохо

  • React
  • Node
  • База данных

Какой React? Какая база? ИИ выдумает.

✅ Хорошо

  • Next.js 16 (App Router) + TypeScript
  • Tailwind CSS 4 + shadcn/ui
  • Supabase + @supabase/ssr
  • OpenAI gpt-4o-mini
  • Vercel
⚙️ Секция 3: «Главные функции»

Цель: 5–10 пунктов, что пользователь делает на сайте. Каждый пункт — мини-история: «открыл → сделал → увидел».

❌ Плохо

«Авторизация и регистрация»

Какая авторизация? По email? Через Google? Магик-линк? Пароль?

✅ Хорошо

Вход по магик-линку
— Пользователь вводит email на странице /login
— Получает на почту ссылку, кликает
— Попадает на дашборд
— Никаких паролей

Совет: думайте от пользователя, не от технологии. Сначала «что он делает», потом «как это сделано».
🗄️ Секция 4: «Структура базы данных»

Цель: для каждой таблицы — поля с типами. Это позволит ИИ написать миграции и валидацию без догадок.

пример из PRD Money Tracker
### Таблица `transactions`

| Поле          | Тип               | Обязательное | Описание                          |
| ------------- | ----------------- | ------------ | --------------------------------- |
| `id`          | `int8`, PK, auto  | Да           | Уникальный номер                  |
| `amount`      | `numeric(10,2)`   | Да           | Сумма с копейками                 |
| `type`        | `text`            | Да           | `"income"` или `"expense"`        |
| `category`    | `text`            | Да           | Категория (Еда, Транспорт и т.д.) |
| `description` | `text`            | Нет          | Комментарий, до 280 символов      |
| `date`        | `date`            | Да           | Дата транзакции                   |
| `created_at`  | `timestamptz`     | Да, auto     | Когда запись создана              |

Не уверены в полях? Это нормально. Пишите минимум, который точно нужен. Остальное добавится по ходу разработки.

📋 Секция 5: «Этапы разработки»

Цель: в каком порядке делать. Task Master будет следовать этому порядку при генерации задач.

Универсальное правило: фундамент → данные → действия → красота → деплой.

типичный порядок
1. Настройка проекта (Next.js + Supabase подключение)
2. Создание таблиц в БД
3. Чтение данных (отображение списка)
4. Создание данных (форма добавления)
5. Редактирование / удаление
6. Дополнительные функции (фильтры, поиск)
7. UI-полировка (анимации, оформление)
8. Деплой на Vercel
Антипаттерн: начинать с красоты. Сначала делайте «уродливое, но работающее». Анимации и шрифты — в конце, когда логика уже работает.
🚫 Секция 6: «Чего НЕ делаем в этой версии»

Цель: явно отрезать «хотелки на потом». Без этой секции ИИ может попытаться запихнуть в задачи всё подряд.

пример
## Чего НЕ делаем в этой версии

- Авторизация — будет в Модуле 7, сейчас открытый доступ
- Категории как отдельная таблица — храним как строку
- Графики и аналитика — позже
- Мобильное приложение — только веб
- Загрузка чеков (фото) — не сейчас
Психологический бонус: когда вы явно записали «авторизацию не делаем сейчас», у вас перестаёт зудеть мысль «надо бы добавить». Ясный scope — спокойная голова.
Практика: набросайте свой PRD

Возьмите идею своего проекта (любую — будильник с мотивирующими фразами, трекер привычек, копилку рецептов — что угодно) и заполните минимально жизнеспособный PRD:

prd-draft.md — ваш черновик
# [НАЗВАНИЕ ПРОЕКТА]

## О проекте
[Две фразы]

## Технический стек
- Next.js 16, TypeScript
- Tailwind 4
- Supabase + @supabase/ssr
- Vercel

## Главные функции
1. ...
2. ...
3. ...

## Чего НЕ делаем
- ...

Если застряли на функциях — переходите к уроку 3. Там claude.ai сам возьмёт у вас интервью и поможет всё структурировать.
