1. Архитектура за 60 секунд

Любое современное веб-приложение — это 3 слоя:

🖥️ Frontend
То, что видит юзер Кнопки, формы, экраны Браузер пользователя
⚙️ Backend (API)
Бизнес-логика Проверки, расчёты Связь с внешним миром
🗄️ Database
Где живут данные Юзеры, посты, заказы Сохраняется навсегда
Аналогия — ресторан:
  • Frontend = зал, столы, меню — то, что видит гость
  • Backend = официант + кухня — принимает заказ, готовит
  • Database = склад с продуктами — где всё хранится

Гость → Официант → Кухня → Склад. И обратно. Это вся архитектура.

Всё. Дальше — карта территории на конкретных примерах.

2. Архитектура на трёх знакомых приложениях

Чтобы стало понятнее, разложим по слоям приложения, которыми вы пользуетесь каждый день:

Как устроен Instagram

Слой Что это в Instagram
🖥️ Frontend Лента, профиль, кнопка "Лайк", истории — всё, что вы видите в приложении
⚙️ Backend Алгоритм рекомендаций, проверка спама, отправка уведомлений
🗄️ Database Профили, посты, лайки, комментарии, подписки
📦 Файлы (storage) Фото и видео — хранятся отдельно, не в БД
🔌 Внешние сервисы Push-уведомления (Apple/Google), оплата (Apple Pay)

Как устроен Uber / Yandex Go

СлойЧто это в Uber
🖥️ Frontend Карта, кнопка "Заказать", иконка машины, цена
⚙️ Backend Расчёт цены, поиск ближайшего водителя, маршрут
🗄️ Database Поездки, водители, пассажиры, оценки
🔌 Внешние сервисы Google Maps (карта), Stripe (оплата), SMS (Twilio)
⚡ Realtime Машина едет по карте в реальном времени — отдельный канал связи

Как устроен ChatGPT

СлойЧто это в ChatGPT
🖥️ Frontend Окно чата, поле ввода, кнопка "Отправить", история диалогов слева
⚙️ Backend Передаёт ваш вопрос в AI-модель, считает использование токенов
🗄️ Database Аккаунты, история чатов, настройки, подписки
🤖 AI-модель GPT-5 — отдельный сервис, который генерит ответы
🔌 Внешние сервисы Stripe (оплата), Auth0 (логин), Sentry (мониторинг ошибок)
Главный инсайт: архитектура одинакова. Что Instagram, что ChatGPT, что Uber — все построены на одних и тех же 3 слоях + внешние сервисы. Меняется только начинка.

4. Что НЕ надо делать на этом этапе

Самые частые ошибки начинающих архитекторов:

❌ "Сразу делать своё, без аналогов"

Изобретать свою БД, свой фреймворк, свой хостинг — путь в никуда. Используйте проверенные решения: Next.js + Supabase + Vercel + Clerk + Stripe. На этом стеке построены тысячи стартапов. Зачем изобретать колесо?

❌ "Микросервисы с первого дня"

Видели на конференции, что Netflix использует 700 микросервисов? У них 200 миллионов юзеров. У вас — пока 0. Начинайте с монолита (одно приложение Next.js), разделять на сервисы будете, когда упрётесь в проблему. До этого — лишняя сложность.

❌ "Своя БД на VPS за $5"

Купить сервер на DigitalOcean и установить PostgreSQL руками — звучит круто. Но: бэкапы, обновления, безопасность, мониторинг — всё это ваша забота. Supabase делает это бесплатно (до определённых лимитов). Время — дороже $5.

❌ "Сразу Kubernetes / Docker / CI/CD pipeline"

Vercel делает деплой за 1 клик. git push → через 2 минуты живой сайт. Никаких docker-файлов, конфигов, helm-чартов. Когда у вас будет миллион юзеров — обсудим. Сейчас — просто Vercel.

❌ "Перебрать 10 фреймворков перед началом"

Next.js vs Remix vs SvelteKit vs Nuxt? Не важно. Все они хорошие. Разница — в нюансах, которые видны только через год. Берите Next.js — у него самое большое комьюнити, лучшая совместимость с AI-инструментами и Vercel.

Принцип vibecoding: «Делай как все. Когда заработает — оптимизируй».
