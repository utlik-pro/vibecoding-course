1. Архитектура за 60 секунд (вся теория, что вам нужна)

Любое современное веб-приложение — это 3 слоя:

🖥️ Frontend
То, что видит юзер Кнопки, формы, экраны Next.js + React
⚙️ Backend (API)
Бизнес-логика Проверки, расчёты, AI-вызовы Next.js API Routes
🗄️ Database
Где живут данные Юзеры, посты, платежи Supabase (PostgreSQL)
Аналогия — ресторан:
  • Frontend = зал, столы, меню (то, что видит гость)
  • Backend = официант + кухня (принимает заказ, готовит)
  • Database = склад с продуктами (где всё хранится)

Гость → Официант → Кухня → Склад. И обратно. Это вся архитектура.

Всё. Теория закончилась. Дальше — только практика. Вы научитесь архитектуре через то, что сделаете руками за следующие 30 минут.

2. Что строим — ContentBot

ContentBot — SaaS-приложение, которое генерирует посты для соцсетей с помощью AI. Юзер логинится, выбирает тему и платформу (Instagram / LinkedIn / X), нажимает "Сгенерировать" → получает 3 варианта поста.

Почему именно этот проект

  • 📦 Покрывает весь стек: фронт + API + БД + AI + биллинг
  • ⚡ Можно собрать MVP за 1-2 часа с помощью AI-инструментов
  • 💰 Реальная бизнес-модель: $9/мес за безлимит — это работает на рынке
  • 🎯 На таком же шаблоне строятся 80% современных AI-стартапов

🛠 ПРАКТИКА 3 — Создаём первый API endpoint (10 мин)

Что делаем: добавляем Backend-слой. Создаём файл src/app/api/generate/route.ts.

Промпт для AI

Prompt 
Создай API endpoint POST /api/generate в Next.js App Router.
Принимает JSON: { topic: string, platform: 'instagram' | 'linkedin' | 'twitter' }.
Возвращает 3 варианта поста-заглушки (без реального OpenAI пока).
TypeScript, использует NextResponse. Добавь валидацию входных данных через zod.

Готовый код, который вы получите

src/app/api/generate/route.ts 
import { NextResponse } from 'next/server';
import { z } from 'zod';

const schema = z.object({
  topic: z.string().min(3).max(200),
  platform: z.enum(['instagram', 'linkedin', 'twitter']),
});

export async function POST(req: Request) {
  const body = await req.json();
  const parsed = schema.safeParse(body);

  if (!parsed.success) {
    return NextResponse.json({ error: 'Invalid input' }, { status: 400 });
  }

  const { topic, platform } = parsed.data;

  // Заглушка — позже подключим OpenAI
  const posts = [
    `Вариант 1 про "${topic}" для ${platform} 🚀`,
    `Вариант 2 про "${topic}" для ${platform} ✨`,
    `Вариант 3 про "${topic}" для ${platform} 💡`,
  ];

  return NextResponse.json({ posts });
}

Проверяем — отправляем запрос

Terminal 
curl -X POST http://localhost:3000/api/generate \
  -H "Content-Type: application/json" \
  -d '{"topic":"Запуск кофейни","platform":"instagram"}'

Поздравляю — вы только что построили коммуникацию Frontend ↔ Backend. Запрос ушёл, ответ вернулся. Это архитектура.

🛠 ПРАКТИКА 4 — Подключаем БД через Supabase (10 мин)

Что делаем: добавляем Database-слой. Создаём таблицы и сохраняем сгенерированные посты.

Шаг 1. Откройте Supabase SQL Editor

В вашем проекте Supabase (создан в Уроке 4.1) → SQL Editor → New query → вставьте:

SQL 
-- Таблица постов
create table posts (
  id uuid primary key default gen_random_uuid(),
  user_email text not null,
  topic text not null,
  platform text not null check (platform in ('instagram','linkedin','twitter')),
  content text not null,
  created_at timestamptz default now()
);

-- Индекс для скорости
create index idx_posts_user_email on posts(user_email);

-- RLS — пользователь видит только свои посты
alter table posts enable row level security;

create policy "users see own posts"
  on posts for select
  using (user_email = auth.jwt() ->> 'email');

Нажмите Run. Откройте Table Editor — вы увидите таблицу posts. Это слой Database.

Шаг 2. Подключаем Supabase к Next.js

Terminal

Создайте файл .env.local и добавьте ключи (из Supabase → Settings → API):

Шаг 2. Импортируйте проект в Vercel

  1. Откройте vercel.com/new
