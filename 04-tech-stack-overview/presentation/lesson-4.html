Базы данных: где живут ваши данные

Цели урока:

  • Понять, что такое база данных (на примере Excel)
  • Узнать, как данные связаны между собой
  • Выучить термины для работы с AI
Философия вайбкодинга: Вам не нужно учить SQL. AI напишет запросы за вас. Ваша задача — понимать структуру данных и правильно её описывать.
Заметка для преподавателя

Ключевой посыл: База данных = Excel в облаке. Студенты не будут писать SQL — они будут описывать структуру данных для AI.

Демо: Покажите интерфейс Supabase Table Editor — он выглядит как Excel.

2. Как выглядят данные

Пример таблицы users (пользователи):

id (ключ) name email created_at
1 Анна anna@mail.ru 2024-01-15
2 Борис boris@gmail.com 2024-01-16
3 Вика vika@yandex.ru 2024-01-17
id (Primary Key) — уникальный номер каждой записи. Как номер паспорта — не повторяется.
3. Связи между таблицами

Таблицы могут быть связаны друг с другом. Например, у пользователя могут быть заказы:

👤 users
🔑 id
name
email
→
📦 orders
🔑 id
🔗 user_id
total
status

user_id в таблице orders ссылается на id в таблице users

🔑

Уникальный номер

У каждой строки свой номер, как номер паспорта. Обычно называется id. Разработчики говорят «primary key», но вам это слово знать не обязательно.

🔗

Ссылка на другую таблицу

Чтобы заказ "знал" своего хозяина, в нём пишут user_id — номер пользователя из таблицы users. Разработчики говорят «foreign key».

Главное: в каждой таблице есть колонка id (уникальный номер). Если в другой таблице нужно сослаться на эту строку — пишут номер в колонке вида что-то_id. Всё. Это вся теория связей.

6. Словарь — если встретите эти слова (не обязательно учить)
Зачем эта таблица: когда вы попросите AI создать базу — он в своих ответах будет использовать эти слова. Не пугайтесь: вы можете отвечать ему по-русски. Эта табличка — чтобы вы понимали, ЧТО он имеет в виду.
Что говорит AI Что это значит на русском Пример из жизни
Table Таблица с данными (как лист в Excel) «Список клиентов»
Row / Record Одна строка в таблице «Один клиент»
Column / Field Колонка (например: имя, email) «Колонка 'телефон'»
Primary Key Уникальный номер строки Как номер паспорта
Foreign Key Ссылка на строку из другой таблицы «В заказе указан номер клиента»
JOIN Соединить данные из двух таблиц «Список заказов вместе с именами клиентов»
Query Запрос — получить данные по условию «Все заказы за вчера»
Schema Структура базы — какие таблицы и колонки «Чертёж дома»
Migration Изменение структуры базы «Добавить новую колонку»

💡 Через 2-3 недели курса эти слова перестанут пугать. А пока — просто знайте, что они существуют.

7. Как описывать данные для AI
Главный принцип: вам НЕ нужно знать слова primary key, foreign key, timestamp. Опишите по-русски, что должно храниться — AI сам выберет правильные технические поля.

Сравните: плохой и хороший промпт

❌

Слишком общо

«Сделай базу данных для интернет-магазина»

AI начнёт додумывать — получите случайные таблицы, которые могут не подойти.

✅

Конкретно и по-русски

«У меня магазин одежды. Нужно хранить товары, заказы и клиентов. Опиши, какие таблицы нужны и что в них хранить.»

AI задаст уточняющие вопросы и предложит структуру.

Уровень 1 — для тех, кто только начинает

Просто опишите словами, что нужно хранить. Никаких терминов:

Промпт на чистом русском
Я делаю сайт с отзывами на товары.
Мне нужно хранить:
- сами отзывы (кто написал, о каком товаре,
  оценка от 1 до 5, текст, когда написали)

Создай нужные таблицы в Supabase.
Объясни простыми словами, какие поля и зачем.

Что произойдёт: AI сам решит, что нужен primary key, что user_id должен быть связан с таблицей пользователей, что дата ставится автоматически. Вам не надо это знать — это работа AI.

Уровень 2 — когда захочется уточнить

Если AI сделал не совсем то — добавьте детали по-русски:

Промпт с уточнениями
Создай таблицу для отзывов:
- кто написал отзыв (связь с пользователем)
- о каком товаре (связь с товаром)
- оценка — число от 1 до 5
- текст отзыва (можно оставить пустым)
- дата отзыва (заполняется автоматически)

Каждый отзыв должен иметь свой уникальный номер.

Видите? Никаких primary key, foreign key, timestamp. Только русские слова: «связь», «уникальный номер», «заполняется автоматически». AI всё переведёт на технический язык сам.

Уровень 3 — если хочется говорить как разработчик (не обязательно)

Через несколько недель курса вы и сами начнёте использовать термины — потому что это короче. Но это не обязательно для старта. Сравните:

По-русски (всегда работает) На техническом (короче)
уникальный номер записи primary key
ссылка на запись из другой таблицы foreign key
дата и время timestamp
обязательное поле / нельзя оставить пустым NOT NULL / required
можно оставить пустым nullable / optional
текст text / varchar
число number / integer
да/нет boolean
Запомните: AI понимает оба языка одинаково хорошо. Начинайте с русского, термины подцепите по дороге. Самая большая ошибка новичка — пытаться сначала «выучить термины», а потом начать делать. Не нужно. Делайте.

Главное из урока
  • База данных — это Excel в облаке: таблицы, строки, колонки
  • id — уникальный номер каждой строки. У всех строк он разный, как номер паспорта
  • Связь между таблицами — это просто номер из одной таблицы, записанный в другой (например, в заказе указан номер клиента)
  • 4 операции с данными: создать, прочитать, изменить, удалить
  • Supabase — это визуальный интерфейс к базе, как Excel в браузере
  • Вам НЕ нужно знать SQL и термины. Описывайте AI на русском, что хотите хранить — он сделает всё остальное
Контрольный вопрос самому себе: можете ли вы описать на русском, какие таблицы нужны для вашего проекта и что в них будет лежать? Если да — вы готовы к Модулю 8, где будем создавать настоящую базу.
